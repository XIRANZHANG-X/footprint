# 后台轨迹的耗电和稳定性、打磨程度：Polarsteps 怎么做，我们怎么做（2026-11-25 调研，待定）

用户认为现在最关键的两件事是：**后台轨迹的耗电和稳定性**，以及**打磨程度**（界面流畅度、各种边缘情况）。
这份文档先列 Polarsteps 公开了什么，再对照我们现在的做法，最后给出要做的事和备选方案。都还没定。

## 一、Polarsteps 公开了什么

**没有找到它的技术博客、会议演讲或工程文章**（搜了 Medium、Bing；DuckDuckGo 要人机验证，没继续）。
能找到的只有它帮助中心里写给用户的说明，但里面透露了不少做法：

| 说的什么                | 原话要点                                                                                                                                  | 来源                                                                                                                                                                                         |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 耗电                    | 后台记一整天大约用 **4%** 电；安卓选"高精度"会高一些；常打开 App 会更高                                                                   | [How much battery does the app use?](https://support.polarsteps.com/hc/en-us/articles/24268094419474)                                                                                        |
| **不是实时追踪**        | 位置**不实时同步上传**，因为不想耗电                                                                                                      | [How does the Travel Tracker work?](https://support.polarsteps.com/hc/en-us/articles/24266585115026)                                                                                         |
| 安卓两种模式            | **省电（Balanced）**：主要用基站和 Wi-Fi，精度中等，**用得最多**；**高精度**：主要用 GPS，耗电高，是默认选项                              | 同上                                                                                                                                                                                         |
| **iPhone 不主动用 GPS** | iOS 版主要靠 Wi-Fi 和基站定位，**不主动开 GPS**；别的 App（比如导航）在用 GPS 时，它顺带收到。更新频率由系统决定                          | 同上                                                                                                                                                                                         |
| 出海                    | iPhone 在海上基本不记；安卓要选高精度才行；没 GPS 时退回 Wi-Fi/基站，会出现**成堆的错点**                                                 | [Does Polarsteps work at sea?](https://support.polarsteps.com/hc/en-us/articles/24266405114130)                                                                                              |

| 离线                    | 没网照样记；联网后自动同步。iPhone 只在打开 App、解锁屏幕时同步                                                                           | [Does Polarsteps work offline?](https://support.polarsteps.com/hc/en-us/articles/24266379026066)                                                                                             |
| 飞行线                  | 两站距离 ≥200 km 且平均速度 >100 km/h，或距离 >1500 km，画成飞行弧线（我们已照搬）                                                        | [How are flight lines determined?](https://support.polarsteps.com/hc/en-us/articles/24266738102802)                                                                                          |

**从这些能推断出它的思路**（推断，不是它说的）：

1. **省电靠"少用 GPS"，不靠什么黑科技**：大部分人用基站/Wi-Fi 定位，iPhone 干脆不开 GPS。代价是点稀、偶尔有错点。
2. **它要的是"路线的大致形状"，不是轨迹**：点只是"小白点"，用来连线；精确的地点靠用户手动加的"站"。
3. **错点交给用户删，加上"贴合道路"美化**，而不是在算法上死磕。
4. **"4% 一天"是因为点少**：基站/Wi-Fi 定位几乎不额外耗电（手机本来就在连基站和 Wi-Fi），真正耗电的是 GPS 和频繁唤醒 CPU。
5. **稳定性靠引导用户改系统设置**（关电池优化），说明它也没办法完全防住手机厂商杀后台。

## 二、我们现在怎么做（`TrackerService.java`，决策 0022）

- 前台服务 + 常驻通知；系统自带的 `LocationManager`（不依赖谷歌服务）。
- 省电模式：网络定位，最少隔 3 分钟或 100 米；精确模式：再加 GPS，最少隔 30 秒或 20 米。都顺带收"被动定位"（别的 App 拿到的）。
- 精度差于 200 米的点丢掉；点写进本机文件，打开 App 时并进数据库。
- 被系统杀掉后**不自己重启**（`START_NOT_STICKY`）。
- 有一个跳转到"电池优化"设置的按钮。

**和 Polarsteps 比，已经做对的**：默认省电、不实时上传、收被动定位、没网照样记、不依赖谷歌服务（国内手机重要）。

**缺的（按严重程度）**：

1. **被杀了没人知道。** 国内手机（小米、华为、OPPO、vivo）杀后台很狠。服务被杀后不会重启，界面上可能还显示"正在记录"，回来才发现中间空了半天。**这是最影响"稳定性"感受的一点。**
2. **精确模式停下来也一直开着 GPS。** 坐在咖啡馆两小时，GPS 还在找卫星。这是耗电的大头。
3. **没有实测数据。** 不知道一天耗多少电、多久被杀一次、点有多准。没有数据就没法改，也没法说"和 Polarsteps 差不多"。
4. **错点只按精度过滤。** 网络定位偶尔"跳"到几公里外（精度值却报得很好），路线上会出现尖刺。没有按速度剔除，也**不能在地图上点掉错点**（Polarsteps 可以）。
5. **国内手机的网络定位不一定有。** 没有谷歌服务的国产手机，系统的网络定位由厂商提供，有的手机质量差甚至没有。省电模式在这些手机上可能几乎记不到点。要在用户手机上实测。
6. **重启手机后不会恢复记录。**

## 三、轨迹：要做的事（推荐顺序）

### 1. 先测量（推荐先做，其他都依赖它）

> 已做，见决策 0030（选 A，断档提示和按品牌的设置路径一起做了）。

| 备选                                                                                                                                                                   | 取舍                                                                 |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| **A 在 App 里自带"记录体检"**：服务每 15 分钟写一条心跳（时间、电量、是否充电、用的是哪种定位）；回到 App 时算出：记了多久、中间断了几次、每小时耗电多少、点的平均精度 | **推荐**。不用电脑；用户日常出门就能攒数据；断档能直接显示给用户     |
| B 用电脑抓安卓系统的耗电报告（`adb bugreport` + Battery Historian）                                                                                                    | 最准，能分清是谁在耗电；但要连电脑、要会用，只适合我们调试时做一两次 |

验证目标（先定一个，测完再调）：**省电模式一天耗电 ≤ 5%**（对标它的 4%），**精确模式 ≤ 15%**；**一天里断档不超过 1 次**。

### 2. 被杀了要知道、能恢复（稳定性）

- **心跳 + 断档提示**：回到 App 时，如果心跳停了很久，提示"路线在 14:20–17:05 之间没有记到，可能被系统停了"，并给出去设置里放行的入口。
- **引导放行**：第一次开记录时，按手机品牌（小米 / 华为 / OPPO / vivo / 其他）给出具体的设置路径（"自启动""后台高耗电""电池优化"），参考 dontkillmyapp.com 的整理。Polarsteps 也是这么做的，只是没按品牌细分。
- **自动恢复**：

| 备选                                                                                                    | 取舍                                                                                       |
| ------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| **A 被杀后由系统定时任务（WorkManager）每 15 分钟检查一次，记录开着但服务不在就重新拉起；开机后也拉起** | **推荐**。安卓 12 起后台不能随便开前台服务，但"已获得始终允许定位"时可以；所以要配合下一条 |
| B 只提示，不自动恢复                                                                                    | 最简单，但用户回来才发现                                                                   |

要做 A，需要用户给"**始终允许**"定位权限（现在只要"使用时允许"）。这是一个隐私上的取舍，要用户决定。

### 3. 停下来就关 GPS（耗电）

- 用手机的"**显著运动**"传感器（`TYPE_SIGNIFICANT_MOTION`，芯片里专门做的，几乎不耗电）判断是否在动：
  停留超过 5 分钟就关掉 GPS，只留网络和被动定位；传感器一触发（开始走动）再打开 GPS。
- 和已有的"停留点"（20 分钟、150 米）不冲突，反而让停留点更省电。
- 备选：用加速度计自己判断（更灵活，但要一直唤醒 CPU，不推荐）；或者什么都不做，只靠用户选省电模式（精确模式会一直很耗电）。

### 4. 错点（点的质量）

- **按速度剔除尖刺**：一个点相对前后两点要以超过 300 km/h 的速度来回跳，而前后两点很近，就丢掉。在手机写进数据库前做，原始点保留在文件里一段时间，方便以后调参数。
- **地图上点掉错点**：照 Polarsteps 做，点小白点 → 删除。
- 备选：卡尔曼滤波平滑整条轨迹——效果更好但复杂，点稀的时候（省电模式）意义不大，不推荐先做。

### 5. 网络定位不可用时（国内手机）

- 先在用户手机上测（第 1 步的体检会显示"网络定位从来没出过点"）。
- 如果确实没有：省电模式改成"GPS 低频"（每 5 分钟开一次 GPS 拿一个点再关），比一直开省很多。
- 备选：接入高德定位 SDK（国内网络定位质量好），但它要采集设备信息、有隐私合规要求，而且又多一个第三方，**不推荐**，除非实测后实在不行。

## 四、打磨：要做的事

"打磨"范围很大，先分成三类，每类都**先测出问题再改**。

### 1. 流畅度（大量数据下）

- **造一份大数据**：脚本生成 2000 条记录、6000 张照片、10 万个轨迹点，导入后测。现在的测试数据只有几条，看不出问题。
- **在手机级的 CPU 上测**：Playwright 用 Chrome 的"CPU 降速 4 倍"模拟中端手机，量这些操作的耗时：打开 App、滚动时间线、打开地图、搜索、生成回看、备份。设一个预算（比如打开 ≤ 2 秒、滚动不掉帧），超了就改。
- 已知会出问题的地方：时间线一次渲染全部记录（backlog 里记过"几百条以后再改成分批加载"）、地图一次画全部轨迹点。
- 加进自动测试，以后每次改动都跑，防止变慢（ideas 六.8 的体积预算检查一起做）。

### 2. 边缘情况（先列清单，逐条写测试）

| 类别     | 例子                                                                                 |
| -------- | ------------------------------------------------------------------------------------ |
| 时间     | 出国后的时区（照片时间按当地还是手机时间）、跨日期变更线、夏令时、没有拍摄时间的照片 |
| 照片     | 很大的照片、HEIC、截图、重复导入同一张、微信传过来没有 GPS 的                        |
| 存储     | 手机空间满了、浏览器清了数据、备份文件损坏                                           |
| 网络     | 弱网、请求到一半断网、服务端超时                                                     |
| 权限     | 拒绝定位、拒绝麦克风、拒绝通知、权限中途被收回                                       |
| 生命周期 | 保存到一半切走 App、被系统杀掉、来电打断录音                                         |
| 数据     | 0 条、1 条、一次出行 200 条、很长的正文、表情符号                                    |

### 3. 出问题时能知道（不上传的前提下）

- **本机问题记录**：报错、崩溃、超时都记进本机的一张表（不上传，和用量表一样），设置里能看、能导出给我分析。
- 现在 `ErrorBoundary` 只在界面上显示错误，关掉就没了。

## 五、建议的顺序

1. **轨迹体检 + 断档提示**（三.1、三.2 的提示部分）：先让你出门一两天就能拿到真实数据。
2. **你实测一两天**：省电和精确各一天，带回数据。
3. 按数据决定：**停下来关 GPS**（三.3）、**自动恢复**（三.2，要你决定给不给"始终允许"）、**错点处理**（三.4）、**网络定位替代**（三.5）。
4. **大数据流畅度测试**（四.1），按结果改时间线分批加载和地图画点。
5. **边缘情况清单**逐条补测试（四.2），**本机问题记录**（四.3）。
