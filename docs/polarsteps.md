# 向 Polarsteps 借鉴什么（2026-11-24 调研，都还没定）

Polarsteps 是荷兰的旅行 App：自动记录路线、给亲友"跟着看"、计划行程、回看和打印成书。
官网说有 2300 万以上用户，帮助中心说记录过 2500 万次以上的出行。它是和我们最接近的产品。

**怎么查的**：

- 官网首页。
- 帮助中心全部 259 篇文章的目录，以及其中约 30 篇相关文章的正文（2026-11-24 查阅）。
- 下面"它怎么做"都是按帮助中心的说法概括的，没有实际装过它的 App。
- **关于"接入 Instagram 好友"**：帮助中心里没有这个功能。它的好友是自己的关注体系，
  Instagram 只出现在"短视频可以自己转发过去"和"不能自动发到 Instagram"。

**规则**：

- 只借功能和思路，不用它的名称、图标、界面、文案（和对待遇见集的规则一样）。
- 每一项真正开工前，照旧单独讨论方案并写进 `docs/decisions/`。
- 推荐程度：★★★ 建议先做；★★ 值得做；★ 以后再说；✗ 不建议。
- **你点名要做的四项**：自动记录路线、跟着看、隐私、规划。它们是第一到第四节，
  其中前两项和已定的决策 0003、0002 冲突，做的话要改写那两份决策（见每节末尾）。

## 一览

| 方面     | Polarsteps                               | 我们现在                                 |
| -------- | ---------------------------------------- | ---------------------------------------- |
| 数据在哪 | 账号 + 云端                              | 只在手机里，没有账号（0002）             |
| 路线     | 后台定位，自动画线                       | 照片里的位置；地图上只有点，没有线       |
| 文字     | 自己写                                   | AI 整理，还会学你的改法（我们独有）      |
| 给别人看 | 关注（要账号）或不用账号的链接           | 只有分享图                               |
| 隐私     | 每个行程三档可见范围、隐藏家和实时位置   | 数据不出手机，所以还没做分享时的隐私控制 |
| 计划     | 计划页、航班住宿、AI 行程、发现页        | 没有                                     |
| 回看     | 统计、短视频、印刷书和海报、路线回放     | 统计、回顾页、出行总结、五种分享图       |
| 怎么赚钱 | 印刷书、订阅、订房佣金；不放广告不卖数据 | 不赚钱，自用后开源                       |

## 一、自动记录路线（你点名要做）

**它怎么做**：

- 一次"出行"里打开"轨迹记录"，之后在后台自动记位置，地图上出现小白点。
  不是实时上传；没网照样记，有网再同步。
- **安卓两档**：
  - 省电档：主要靠基站和 WiFi，精度中等；
  - 高精度档：主要靠 GPS，是默认档。
- **iPhone**：主要靠 WiFi 和基站；别的 App 用 GPS 时，它顺带拿到。
- **耗电**：官方说全天记录约 4% 电量。
- **地点建议**：到了新地方，时间线上出现"要不要加一站"；点了才变成正式的一站，带照片和文字。
- **画线**：所有点按时间连起来。两点相距 ≥ 200 公里且平均时速 > 100 公里，或者相距 > 1500 公里，画成飞行弧线。
- **每段路可以设交通方式**，显示成图标；可选"贴合道路"，把直线换成最可能走的路。
- **不准的点**可以删掉，但删了加不回来。
- **结束出行**：没有"结束"按钮，设结束日期，到那天午夜自动结束；早到家就先关掉记录。
- **不能导入 GPX 轨迹文件**。
- **掉点的常见原因**：安卓的省电模式、系统的"电池优化"（要把 App 排除在外）、飞行模式。

**对我们**：

- 决策 0003 当时不做后台轨迹，理由是耗电、隐私敏感、必须是原生 App。
  现在 App 已经是原生外壳（0009），"必须原生"不再是障碍，耗电和隐私仍然要正面解决。
- **国产安卓手机的坑**：
  - 很多国产手机没有谷歌服务，谷歌的融合定位用不了，要直接用系统自带的 GPS 和网络定位；
  - 厂商的后台管理很凶（自启动、电池优化、后台冻结），要引导用户把 App 加进白名单，否则锁屏后就停了。
- **安卓的权限流程**：
  - 安卓 10 起，后台定位要单独申请"始终允许"；
  - 安卓 11 起，这个权限不能在弹窗里直接给，要跳到设置页；
  - 持续记录要开"前台服务"，通知栏会常驻一条"正在记录路线"；安卓 14 起还要声明定位类的前台服务权限。
- **只有安卓 App 能做**：网页版和 iPhone 的网页版做不了后台定位。
- **坐标系不用转换**：GPS 给的是 WGS-84，和现在的 OSM 地图一致。

| 备选                                                                                                      | 取舍                                                     |
| --------------------------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| **A 出行时手动开启的后台记录**（前台服务 + 常驻通知）。省电档每隔几分钟或走了几百米记一个点；点只存手机里 | **推荐**。和它的做法一样；用户知道什么时候在记，耗电可控 |
| B 只在 App 打开时记，再用照片位置补（现状加一点）                                                         | 几乎不耗电，但路线断断续续                               |
| C 全天自动记，不用开启出行                                                                                | 最省事，但最耗电、最敏感，在国产手机上最容易被杀         |
| D 导入别的 App 的轨迹（GPX，例如两步路、六只脚、运动手表导出的）                                          | 便宜，可以和 A 一起做；它没有这个功能                    |

**推荐 A + D**，再加两个：

- **停留点识别**：在一个地方附近停留超过 20 分钟左右，就提示"在这里停了 1 小时，要记一条吗？"。
  加上那段时间拍的照片，最贴近"懒得整理"这个初衷，也就是 `docs/ideas.md` 四.3"主动发现出行"的轨迹版。
- **按速度猜交通方式**，并画飞行弧线（见第五节第 1、2 条）。

**插件**：

- 社区插件 `@capacitor-community/background-geolocation` 免费。要先确认它在没有谷歌服务的手机上能不能用，
  不行就自己写原生的前台服务，用系统的定位接口。
- 商业插件（Transistor Software 的那个）安卓正式版要付费授权，不选。

**代价**：大。要写原生代码，处理权限流程，实测耗电，适配国产手机。

**要改的决策**：0003 的"不做后台轨迹"。

## 二、跟着看（你点名要做）

**它怎么做**：

- **两种看法**：
  - **关注**：对方要有账号，你批准后，他能看你所有"关注者可见"的行程；你每发一站，他收到推送，能点赞、评论。
  - **秘密链接**：不用账号、不用装 App，打开网页就能看路线和每一站；链接被转发出去，别人也能看。
- **关注的是人，不是某次行程**：不能指定"这个人只看这次"；想只给某些人看，就只发链接、不批准关注。
- **像"故事"一样翻看**：一站一站翻，点左右换照片，按住暂停，滑到下一站，显示"第几天"。
- **不能自动发到 Instagram、Facebook**；2026 年 11 月起，也不能再把地图嵌到自己的网站。

**对我们**：0002 定的是"不做账号、服务端不存任何用户数据"，所以有三档：

| 备选                                           | 取舍                                                   |
| ---------------------------------------------- | ------------------------------------------------------ |
| A 只发分享图（现状）                           | 最简单，但朋友看不到路线，也不会随着出行更新           |
| **B 加密的只读行程链接，不做账号**（细节见下） | **推荐**。接近它"不用账号的秘密链接"，服务器读不了内容 |
| C 账号 + 关注 + 推送 + 评论（像它一样）        | 见下，现在不建议                                       |

**B 怎么做**：

- 手机上把这次出行的路线、每一站的文字和缩小的照片打包，用随机生成的钥匙加密（浏览器自带的 AES-GCM），
  上传到 Cloudflare R2（对象存储）。
- 钥匙只放在链接 `#` 后面。浏览器不会把 `#` 后面的内容发给服务器，所以服务器存的是它自己解不开的数据。
- 朋友打开链接：网页下载数据，在浏览器里解密，显示地图和每一站。
- 出行中每记一条，就自动重新上传一次；朋友刷新就能看到新的一站。
- **能做到**：不用账号、不用装 App；随时撤回（删掉服务器上的文件）；可以设有效期。
- **做不到**：
  - 推送通知：没有账号，就没法推。
  - 点赞、评论：要么不做，要么做"留言"（下面的 B+）。
- **存储**：R2 每月有免费额度，下载流量不收费。一次出行 50 张照片，按长边 1280 像素算约 10 MB。
- **前提**：先实测大陆网络能不能打开 workers.dev（0007 记过还没测）。打不开，这个功能就没意义，要按 0007 的兜底方案换域名。

**B+ 留言**：看的人写一句话、填个昵称，用同一把钥匙加密后附加存上去，你在 App 里能看到。
只有拿到链接的人能写、能看，不做点赞计数。工作量中等。

**为什么现在不做 C**：

- 账号：国内基本要用手机号短信登录，短信按条收费。
- 还要数据库，还有推送：国产手机没有谷歌推送，要分别接各厂商的推送。
- 公开的用户内容要做审核，还牵涉备案。
- 冷启动：朋友得先装 App。
- 0002 当时就是因为这些没选它。

**要改的决策**：0002 的"服务端不存任何用户数据"，改成"服务端只存它读不了的加密数据，用户可以随时删除"。

## 三、隐私（你点名要做）

**它怎么做**：

- **每个行程三档可见范围**：只有自己 / 关注者 / 所有人，默认"关注者"。
  账号这一层，还可以设"谁能关注我"：要我批准 / 任何人，默认要批准。
- **隐藏实时位置**：出行中，关注者看不到你此刻在哪，也看不到最后一站之后的路线；你每发一站，才露出到那一站为止。
- **隐藏家的位置**：起点周围 5 公里内的点对别人隐藏，终点回到圈里也隐藏；
  圆心故意随机偏一点，让人不能从圆推出你家在哪。
- **公开资料**：头像、名字、所在城市对所有人可见，这样别人才搜得到你；它建议用昵称。
- **搜索引擎**：只有行程设成"所有人"，或者链接被公开转发了，才可能被搜到。
- **上传**：只有你点了"发布"的内容才上传；建议的地点和照片，在你确认之前不上传。
- **拿到链接的人**没有账号也能点赞，显示成"匿名"。

**对我们**：数据本来就只在手机里，隐私问题主要出在"分享出去"和"开始记轨迹"这两件事上。可以借的：

| 项                                                                                                                                                                                  | 推荐 |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---- |
| 1. **隐私区**（家、公司等）：半径 500 米到 5 公里，圈内的点在分享、导出、分享图的地图上都去掉，圆心随机偏移（它和 Strava 都这么做）。轨迹一开，起点就是家门口，所以要和第一节一起做 | ★★★  |
| 2. **分享时选内容**：带哪几站、哪几张照片，正文带不带                                                                                                                               | ★★★  |
| 3. **位置模糊**：分享时只精确到城市或区县，或者只显示地名、不显示点                                                                                                                 | ★★★  |
| 4. **链接有效期和撤回**                                                                                                                                                             | ★★★  |
| 5. **实时位置延迟**：出行中，分享链接只更新到"最后一条记录"，不带之后的轨迹                                                                                                         | ★★   |
| 6. **不让搜索引擎收录**：链接页加 `noindex`                                                                                                                                         | ★★   |
| 7. **照片不带拍摄信息**：我们存的照片是重新编码过的，本来就不带 EXIF（拍摄地点、手机型号）；原图从不上传。这一点写进隐私说明即可                                                    | 已有 |
| 8. **打开 App 要指纹或密码**：它没有，但日记类 App 常见，手账很私密                                                                                                                 | ★    |

## 四、规划（你点名要做）

**它怎么做**：

- **一次出行分"计划"和"记录"两个页签**：
  - 计划里加目的地（搜索，或在地图上拖），填到达日期、住几晚、备注（门票号之类）；
  - 拖动可以改顺序；计划太满会提醒。
- **航班和住宿**：
  - 航班按航班号查；住宿可以跳到订房网站，地点和日期自动带过去；
  - 也可以把订票确认邮件转发到它的专用邮箱，自动加进计划。
- **到了计划里的地方**，时间线自动出现"记下这一站"的建议。
  计划的站不能放照片，去过之后才变成普通的一站。
- **AI 行程**：
  - 先读你过去行程里写的文字，生成一份"旅行偏好档案"，比如喜欢博物馆、讨厌转机和人挤人的大城市；
  - 再按你给的国家或城市推荐路线，每个推荐都说明理由；
  - 每月 10 次，是测试中的功能。
- **发现页**：编辑写的目的地指南、别人公开的真实路线、"朋友去过的地方"、收藏夹。
- **一起编辑**：可以和同行的人一起改计划（Travel Together，见第五节第 16 条）。
- **iPhone 小组件**：有计划时显示"离下次出行还有几天"，没有时显示"上次出门是多少天前"。

**对我们**：

| 备选                                                                                                                                                                       | 推荐                                                                                        |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| **A "想去的地方"清单**：随手存（搜地名、在地图上点），按城市分组，地图上用星标显示。以后真的去了（记录的位置在 200 米内），自动标成"去过了"，接上"第一次 / 重逢"和点亮地图 | ★★★ 先做，工作量小、完全本地                                                                |
| **B 一次出行的计划**：目的地、日期、住几晚、备注；地图上计划路线画虚线、实际路线画实线；到了计划的地方，提示"记下这一站"（靠第一节的轨迹或照片位置）                       | ★★ 工作量中                                                                                 |
| **C AI 行程（"像我的"计划）**：细节见下                                                                                                                                    | ★★★                                                                                         |
| D 订票邮件转发                                                                                                                                                             | ✗ 要收用户的邮件，违反 0002。替代做法：把订单截图或文字贴进来，让模型抽出航班、酒店、日期 ★ |
| E 发现页、目的地指南、看别人的路线                                                                                                                                         | ✗ 要编辑团队和社区，不适合个人项目                                                          |
| **F 倒计时**：首页显示"离下次出行还有 12 天"，没有计划时显示"上次出门是 23 天前"。也是让人回来打开的理由。安卓桌面小组件要写原生代码，先做 App 里的                        | ★★                                                                                          |

**C AI 行程怎么做**：

- **思路和它一样，但我们的数据更好**：已经有偏好说明（0012）、你的改稿习惯、每条记录的类别和标签、点亮过的城市。
- **做法**：把你的偏好、去过哪里（检索出来的相关记录，也就是 RAG）、目的地、天数交给模型，产出每天的地点建议。
  - 每个地点都用地名搜索核实，核实不了的标"未核实"；
  - Nominatim 在国内不够准，可以换高德：要申请 key，还要处理坐标偏移，见待办第五档。
- **和 0012"只写你说过的"不冲突**：计划只是建议，不写进手账正文。
- 这也是 `docs/ideas.md` 里 Agent 方向的一个落地点，工具有：搜地名、查"我去过的"、查天气。

## 不建议借的

- ✗ 账号、公开主页、粉丝数、发现页这类社区功能：冷启动、内容审核、违反 0002。
- ✗ 订票邮件转发：要收用户的邮件。
- ✗ 订房跳转赚佣金：商业化，和个人项目无关。
- ✗ 印刷实体书：要管印刷、物流、退货。改做 PDF（第五节第 8 条）。
- ✗ 3D 地形：代价大，收益主要是好看。
