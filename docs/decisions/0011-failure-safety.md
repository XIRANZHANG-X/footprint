# 0011 出错时不卡死、不丢数据

- 状态：已定（2026-11-10）

## 背景

整理待办清单（`docs/backlog.md`）时发现四个"出了事没法补救"的问题，都不大，一起处理：

1. AI 整理到一半时关掉 App，记录永远停在"整理中"，这个状态下没有重试按钮。
2. 界面任何一处渲染出错，整页变白，没有任何提示。
3. 存储空间满了，保存照片会失败，但界面上什么都不显示（错误没人接）。
4. 删除是永久的，只靠一个浏览器确认框拦一下。

## 决定

### 1. 卡在"整理中"

App 启动时把所有停在"整理中"的记录改成"整理失败：上次整理被打断了，请重新生成"。
启动的那一刻不可能有整理任务在跑，所以这样改一定是对的。

| 备选                          | 不选的原因                                                         |
| ----------------------------- | ------------------------------------------------------------------ |
| 启动时自动重新整理            | 会在用户不知情时花模型费用；如果是某条记录本身导致失败，会反复重试 |
| "整理中"状态下也显示重试      | 正在整理时点重试会同时跑两个任务，结果互相覆盖                     |
| 给"整理中"加超时（如 2 分钟） | 要多存一个开始时间；启动时处理已经覆盖了实际会发生的情况           |

### 2. 整页白屏

最外层加一个兜底页：告诉用户"记录和照片还在"，给"重新打开"和"导出备份"两个按钮，并显示出错信息方便排查。
导出备份只读数据库，不依赖出错的界面。

| 备选                 | 不选的原因                                                                     |
| -------------------- | ------------------------------------------------------------------------------ |
| 每张卡片各自兜底     | 一条坏数据只坏一张卡片，体验更好；但要改的地方多，先做最外层这一道，以后再细分 |
| 接入线上错误上报服务 | 要把用户设备上的信息发到第三方，和"服务端不存用户数据"不一致                   |

### 3. 存储空间满

保存和导入备份失败时，识别出"空间不足"这一类错误，用中文说明发生了什么、该怎么办；其他错误也显示出来，不再静默。
保存失败时照片还留在编辑区，腾出空间后可以再点一次"完成"。备份页在占用空间后面加上浏览器给的上限。

| 备选                   | 不选的原因                                                         |
| ---------------------- | ------------------------------------------------------------------ |
| 保存前先估算空间够不够 | 浏览器给的数字只是估计值，照片压缩后的大小也要压完才知道，判断不准 |
| 空间快满时提前提醒     | 有用，但要定阈值、找地方显示；等真的有人遇到再加                   |

### 4. 删除可以撤销

去掉确认框。点"删除"后立即删掉，页面底部出现"已删除这条记录 · 撤销"，6 秒内点撤销就原样放回（包括照片）。
被删的内容这 6 秒只留在内存里：提示消失或 App 关掉后，就真的删了。

| 备选                                | 不选的原因                                                                 |
| ----------------------------------- | -------------------------------------------------------------------------- |
| 保留确认框                          | 确认框拦不住手快点了"确定"的情况，而且每次删除都多一步                     |
| 回收站（标记为已删除，30 天后清理） | 最保险，但要改数据库结构，所有列表、地图、备份都要过滤已删除的记录；先不做 |
| 先不删，6 秒后再真正删              | 这 6 秒里关掉 App，记录会"复活"，和用户看到的不一致                        |

## 验证（2026-11-10，电脑浏览器）

- 把一条记录的状态手动改成"整理中"后刷新：显示"整理失败：上次整理被打断了"，有"重新生成"按钮。
- 删除一条记录：提示出现，点撤销后记录和照片都回来了；不点撤销，6 秒后提示消失，记录已删。
- 往一条记录里写入坏数据让界面出错：出现兜底页，而不是白屏。兜底页上的"导出备份"按钮没有实际点过。
- 空间不足没法在电脑上真实复现，只用单元测试验证了错误的识别和提示文字。
