# 0025 回看：路线回放和短视频、路线海报、PDF 手账、当时的天气（向 Polarsteps 借鉴的第 5 批）

- 状态：已定并实现（2026-11-24）。来源：`docs/polarsteps.md` 第五节第 4、6、8、9、11 条。用户说"全部开始做"，按推荐做。
- 入口：时间线上每次出行的标题旁边多了"回看"按钮，打开后是路线回放，下面三个按钮：存成短视频、路线海报、导出 PDF 手账。
  都在手机上生成，不上传。

## 1. 路线示意图（三样东西共用，推荐 A）

| 备选                                                       | 取舍                                                                      |
| ---------------------------------------------------------- | ------------------------------------------------------------------------- |
| **A 不用地图瓦片，只画路线和按顺序编号的地方（手账风格）** | **选定**。不受瓦片使用条款限制，不用处理跨域；像素风格和分享图一致        |
| B 把地图瓦片画进图片                                       | 好看，但 OSM 和高德的瓦片都不允许随便拿来生成图片，还要处理跨域、坐标偏移 |

- 有轨迹的出行沿轨迹画（0022），远距离的一段画虚线；地方按时间编号，旁边写标题。
- 挤在一起的地方只写编号（离写了名字的地方不到 90 像素），靠右边的名字放到方块左边，不压住方块。

## 2. 路线回放和短视频（推荐 A）

| 备选                                                                       | 取舍                                                                               |
| -------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| **A 画布动画 + 浏览器自带的录制（MediaRecorder），回放和视频是同一段动画** | **选定**。不加依赖；能录 MP4 就录 MP4（Chrome 和安卓 WebView 支持），不能就录 WebM |
| B 用 ffmpeg.wasm 合成视频                                                  | 格式最可控，但要下载 30 MB 左右的 wasm，合成也慢                                   |
| C 不做视频，只做回放                                                       | 发不到朋友圈、视频号                                                               |

- 动画：4 秒画出路线 → 每站一张照片 2.2 秒（慢慢推近，底部写第几站、标题、日期）→ 1.5 秒落款。最多 12 站。
- 竖屏 720 × 1280。要实时播完一遍才能录完，录的时候按钮上写着"录视频中（要播完一遍）"。
- **不配乐**：要用有授权的曲库，先不做。
- 录成 WebM 时提示"微信可能发不了"。

## 3. 路线海报

- 1080 × 1920：标题（去过的城市）、日期和里程、路线示意图、按顺序的地方名单。

## 4. PDF 手账（推荐 A）

| 备选                                                             | 取舍                                                                        |
| ---------------------------------------------------------------- | --------------------------------------------------------------------------- |
| **A 复用长图的排版，按 A5 固定页高分页，每页一张 JPEG 装进 PDF** | **选定**。排版代码现成；PDF 直接嵌 JPEG，自己写一个几十行的生成器，不加依赖 |
| B 用 jsPDF / pdf-lib 排版                                        | 文字可选中、可搜索，但要重写一套排版，多一个几百 KB 的依赖                  |

- 第一页：标题、日期和里程、路线示意图。之后每条记录：标题、日期、地点、天气、正文、最多 4 张照片。
- A5 竖版（148 × 210 毫米），可以直接拿去打印。文字是图片里的，不能选中复制。

## 5. 当时的天气（推荐 A）

| 备选                                   | 取舍                                                  |
| -------------------------------------- | ----------------------------------------------------- |
| **A Open-Meteo，经过我们的服务端转发** | **选定**。免费、不要 key；第三方只看到我们服务端的 IP |
| B App 直接请求 Open-Meteo              | 少一次部署，但用户的 IP 会给到第三方                  |
| C 和风天气等国内服务                   | 要申请 key，历史天气要付费                            |

- 有位置、拍摄时间可靠（照片自带的拍摄时间，或"只写几句"写下的那一刻）的记录，在后台补上当时的气温和天气，
  每次最多 10 条。卡片上显示"🌦️ 小雨 18°C"，PDF 手账里也有。
- 最近两个月用 Open-Meteo 的预报接口（保留过去 92 天），更早的用历史接口。取离拍摄时间最近的那个小时。
- **不交给 AI 写进正文**：天气是查来的事实，可以用，但 0012 定了正文只写用户说的和照片里有的，先不加。
- 发出去的只有坐标和时间，写进 README 的隐私说明；Open-Meteo 的数据协议 CC BY 4.0，写进 THIRD_PARTY.md。

## 验证

- 单元测试：PDF 结构（xref 里每个对象的位置都对得上）；天气接口（按当地时间取最近的小时、早的日期走历史接口、坏参数拒绝）。
- 浏览器里，3 条记录、杭州到上海的出行：
  - 卡片上显示天气标签；"回看"打开后路线回放在播；
  - 海报 128 KB，标题"杭州市 · 上海市"、日期和里程对；挤在一起的断桥和雷峰塔只写了编号，靠右的外滩名字放到了左边；
  - PDF 4 页、391 KB，文件头和结构正确；
  - 录视频：MP4，12.4 秒（计划 12.1 秒），1.5 MB。
- 没验证：手机上录视频（安卓 WebView 是否支持 MP4）、真实天气（要口令，部署后在 App 里看）、PDF 打印效果。
