# 0013 记录的编辑范围和新建流程

- 状态：已定（2026-11-10）

## 背景

待办清单第二档（`docs/backlog.md`）：记录能改的东西太少、照片点不开、AI 猜的地名被当成真的、
不能只写文字、写到一半内容丢失。和 AI 写作风格有关的部分在 0012。

## 决定

### 1. 加删照片后只提示，不自动重新整理

编辑页可以加照片、删照片。照片变了以后，卡片上出现一行"照片有变动，要重新整理吗？"，用户点了才整理。

| 备选               | 不选的原因                                                                       |
| ------------------ | -------------------------------------------------------------------------------- |
| 保存后自动重新整理 | 每次调整照片都花费用、等几秒；只删一张重复照片也会重写；用户改过的正文可能被换掉 |
| 什么都不做         | 容易忘，留下和照片对不上的正文                                                   |

原则和 0011 一致：花钱的操作都要用户点一下才发生。

新加的照片即使带拍摄时间和 GPS，记录本身的时间和地点也不跟着变，仍以原来的为准，要改就在编辑页手动改。
否则补一张第二天拍的照片，整条记录会跳到另一次出行里去。

### 2. 没有定位的记录：先给当天去过的地点供选择，没有就自己输入

（用户 2026-11-10 提出，替换了原先"AI 猜测 → 反查坐标"的方案）

- 同一天如果有别的带定位的照片或记录，把这些地点列出来，用户点一下就用它（地名和坐标一起带过来，直接上地图）。
- 当天没有带定位的照片，就让用户自己输入地名。
- 原有的"在地图上点一下"保留。
- AI 从照片里猜的地名不再直接当成真实地点：只作为一个标着"AI 猜测"的选项和上面的候选放在一起，用户点了才用。

| 备选                                 | 不选的原因                                                           |
| ------------------------------------ | -------------------------------------------------------------------- |
| AI 猜测后用地名反查坐标，列出候选    | 国内小店大多查不到；要新增接口；当天的其他照片是更可靠、更省事的来源 |
| 自动使用反查到的第一个结果           | 重名很常见，放错了用户可能发现不了                                   |
| 自动套用当天其他照片的地点，不问用户 | 一天可能去好几个地方，自动选容易选错                                 |

### 3. 自己输入的地名：查坐标，列出候选让用户选

用户输入地名（或点了"AI 猜测"）后，服务端用这个名字查坐标（Nominatim 的搜索接口，和现有的地名查询同一个来源、
同样限速），列出最多 3 个候选并带上所在城市，用户选一个，记录就放上地图。
查不到或都不对：只保存地名文字，记录留在地图页的"待定位"列表里，之后可以在地图上点。

| 备选                       | 不选的原因                                                     |
| -------------------------- | -------------------------------------------------------------- |
| 只存文字，不上地图         | 最简单，但这些记录在地图上是缺的（用户 2026-11-10 选了查坐标） |
| 输入后直接跳到地图让用户点 | 每次都被强制多做一步                                           |
| 自动用第一个结果           | 重名很常见，放错了用户可能发现不了                             |

已知限制：国内的小店、餐馆大多查不到，景点和地标一般可以。以后换高德（0005 里的备选）能改善。

### 4. 只写文字的记录

"新建"里加"只写几句"入口，允许没有照片的记录。

- 时间：默认是写的那一刻，编辑页可以改（比如补记昨天的事）。
- 地点：按第 2、3 条走；另外多一个"用当前位置"按钮，点了才申请定位权限并取位置。
  这个按钮只在"只写几句"里出现，有照片的记录仍然以照片的定位为准。

| 备选                   | 不选的原因                                                                   |
| ---------------------- | ---------------------------------------------------------------------------- |
| 不用手机定位           | 人在现场时仍然要选或输入一次（用户 2026-11-10 选了加按钮）                   |
| 一打开就自动取当前位置 | 一上来就弹授权框；回家后补记会把记录放在家里；离 0003 说的"不做位置追踪"太近 |

代价：安卓 App 要多声明一项定位权限，第一次点按钮会弹系统授权框；室内定位可能偏几十米。

### 5. 整理提速：先并行，量了再决定下一步

这次只做最便宜的一步：查地名和缩小照片同时进行。同时记下每一步花了多少毫秒，存在记录里，
用几天后看数字，再决定要不要做"边生成边显示"或换模型（0006 里的另外两个选项）。

| 备选                 | 不选的原因                                                                                                         |
| -------------------- | ------------------------------------------------------------------------------------------------------------------ |
| 这次就做边生成边显示 | 服务端接口、返回格式解析、卡片界面都要改；这一档还要改提示词（平实、偏好说明、例子），会影响速度，现在优化可能返工 |
| 换更快的模型         | 要重新测质量，认招牌的能力可能下降；没有耗时数据之前无从比较                                                       |

另外，"直接保存"的记录只需要 AI 补标题和标签（0012），输出很短，本来就快。

## 实现记录

### 2D（2026-11-10）

- 编辑页一次保存这些内容：照片、时间、地名、标题、类别、正文、原话、标签。
- 加删照片在点"保存"时才生效；新照片排在已有照片后面。有照片处理失败时，其他改动照常保存，
  编辑页留着并列出没加进来的文件名。
- "照片有变动"的提示只在 AI 整理过的记录上出现（记录上的 `photosChanged`），点"不用"或重新整理成功后消失。
  正文用的是自己写的那一版时，"重新整理"只重新补标题和标签。
- 改地名只改文字，坐标不动；按地名查坐标在 2E 做。
- 时间输入框只精确到分钟：没动过时间就不写回，原来的秒数和"时间来自照片"的标记都保留；改过之后标记为手动。
- 只改时间、地名或照片，不算一次"修改 AI 的稿子"，不进修改记录（否则会拉低 0012 里的平均改动比例）。
- 看大图用浏览器自带的横向滚动加吸附实现左右滑，没有引入手势库；显示的是存储用的那一版（长边 2048 像素），
  不能双指放大，需要的话以后再加。
