# 0008 访问保护：访问口令

- 状态：已定（2026-11-07）

## 背景

部署到公网之后（决策 0007），任何拿到网址的人都能调用 AI 接口，花的是部署者的百炼额度；
地名接口被滥用，还可能让 OpenStreetMap 封掉我们的服务。
页面本身被人打开没有关系：记录只存在各自浏览器里，别人打开只会看到一个空的 App。

## 决定

用一个**访问口令**保护 `/api/transcribe`、`/api/describe`、`/api/geocode`。

- 口令是一串随机长字符，作为 Cloudflare 的加密环境变量（secret）`ACCESS_TOKEN` 保存，不进仓库，也不进前端代码。
- App 第一次需要 AI 时请用户输入口令，存在浏览器的 localStorage 里，之后每次请求放在 `Authorization: Bearer` 头里。
- 服务端先把两边做哈希再比较（用 Hono 自带的 `timingSafeEqual`），避免通过响应时间逐位猜出口令。
- `/api/health` 不验证口令，只报告"AI 是否已配置、是否需要口令"，用来检查服务是否在线。
- **线上（Worker）没有配置口令时，AI 接口直接拒绝**，而不是放行：忘记配置口令不会让接口裸奔。
  本机开发（Node）没配口令时放行，方便在家里局域网测试。
- 第二道防线（需要部署者自己操作）：在阿里云费用中心设置费用预警，口令泄露时损失有上限、能及时发现。

## 备选方案

| 方案                                | 不选的原因                                                                                                       |
| ----------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| Cloudflare Access（邮箱验证码登录） | 要开通 Zero Trust（可能要绑支付方式）；登录页在大陆可能打不开，那样整个 App 都用不了                             |
| 每人在 App 里填自己的百炼 key       | key 存在浏览器里不如放服务端安全；对部署者本人没有解决"别人花我的额度"的问题。以后开源、给别人自部署时可以再考虑 |
| 完整账号系统                        | 和决策 0002"不做账号"冲突，工程量大                                                                              |

## 已知局限

- 口令泄露后要手动换一个（重新 `wrangler secret put`），所有设备重新输入。
- 把口令告诉朋友，朋友用的也是部署者的额度；需要区分用户时再考虑每人一个口令。
- 没有做限流。个人使用量下，费用预警比限流更简单有效；以后需要再加。
