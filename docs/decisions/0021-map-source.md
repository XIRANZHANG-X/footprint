  第 1 批（0020）"补去过的地方"要点亮国内的城市，缺城市的边界数据。

## 下一步：用户申请 key（只能用户自己做）

1. 到高德开放平台（lbs.amap.com）注册开发者，完成实名认证。
2. 在控制台创建一个应用，名字随意，比如"足迹手账"。
3. 给这个应用加 key，服务平台选 **"Web 服务"**。这个 key 给服务端用：查地名、搜地名、查行政区边界。
4. 再加一个 key，服务平台选 **"Web 端（JS API）"**，它会同时给一个"安全密钥"。这个用来试底图的接法 b，先申请着。
5. 记下控制台里写的免费额度（每天或每月多少次），告诉我，记进这份决策。
6. key 的放法和百炼的一样：
   - 自己写进 `.env`，变量名 `AMAP_WEB_KEY`（Web 服务）、`AMAP_JS_KEY` 和 `AMAP_JS_SECURITY`（JS API）。
   - 不要发在对话里，我不读 `.env` 的内容。
   - 上线前再用 `wrangler secret` 设到服务端。

**用户已填好三个 key（2026-11-24），实测**：

- Web 服务 key 可用：行政区查询"杭州"返回杭州市（城市级，行政区代码 330100）的完整边界，6420 个点、约 134 KB。
  太大，服务端要先简化再传给 App（目标几千字节）。
- 底图接法 a 可行：高德的瓦片地址不用 key 就能取。
  - 普通版 256 像素；`wprd0x.is.autonavi.com/appmaptile?...&scl=2&style=7` 是 512 像素的高清版，
    在手机上不用放大，和高德 App 一样清楚。
  - 底色是奶油色，和 App 的马卡龙配色搭。
  - 风险：这个地址不在高德公开的文档里（文档读不到，见上），哪天改了或者不让用，就退到接法 b
    （高德自己的地图库，用 JS API 的 key）。

不用等 key 就能先做的：WGS-84 和 GCJ-02 的坐标换算（`src/lib/geo/gcj02.ts`）和它的测试。

## 现在用的是什么（0005 定的）

地图在 App 里管三件事，现在全部来自 OpenStreetMap（OSM）：

| 用途                       | 现在                                              | 问题                                                                  |
| -------------------------- | ------------------------------------------------- | --------------------------------------------------------------------- |
| 底图（看到的那张地图）     | OSM 标准瓦片：256 像素的小图片                    | 手机屏幕像素密度高，要放大 2–3 倍，发糊；国内道路、店名少，有的是拼音 |
| 地名（坐标查地名、搜地名） | Nominatim（OSM 的地名服务），经过我们的服务端转发 | 国内小店大多查不到（0006、待办第五档早就记着）                        |
| 边界（点亮区域用）         | 打包的省级和区县边界；地级市没有                  | "去过杭州"没法把杭州涂色                                              |

**模糊有两个原因**：数据少，加上图片分辨率不够。高德、百度、Google 的 App 用的是"矢量地图"，
在手机上按屏幕像素现画，所以清楚。

**坐标系**：手机 GPS 和 OSM 用的是国际通用的 WGS-84。国内的地图按国家规定要加密偏移：
高德、腾讯用 GCJ-02，百度在这之上再偏一次（BD-09）。直接把 GPS 坐标画在高德地图上，会偏几百米。
天地图用国家大地坐标系（CGCS2000），和 WGS-84 只差几厘米到一米左右，可以当成一样。

**合规**：在国内公开发布的地图按规定要有审图号。高德、天地图的底图有；OSM 没有。
自己用没关系，以后给别人用、开源时要考虑。

## 推荐 C 的细节

**要你做的**：

- 到高德开放平台注册开发者（要实名认证），创建一个应用，申请 key。
- 个人非商业使用有免费额度，具体每天多少次申请时核对。
  我们一天的用量很小：每条记录查一次地名，偶尔搜地名、查边界。

**key 放哪**：

- 地名和边界：放在服务端（和百炼的 key 一样，用 `wrangler secret` 设），App 里看不到。
- 底图：要放在 App 里。高德 Web 端的 key 可以限制只能从我们的网址使用，泄露了别人也用不了。具体方式申请时核对。

**坐标怎么处理**：

- 存的永远是 WGS-84，和现在一样，备份、地图点亮、"第几次来"都不用改。
- 画到高德底图上时，把 WGS-84 换成 GCJ-02（公开的算法，误差在米级）。
- 高德返回的地点和边界是 GCJ-02，存之前换回 WGS-84（反算要迭代，误差 1 米左右）。
- 这一层集中在一个文件里，写测试。

**国内国外怎么分**：

- 按地图当前看的区域：中心在国内用高德，出了国用 OSM，切换时底图换一下。
- 地名按坐标在不在国内选服务。

**底图的接法**（还要再定一个小问题，申请 key 后实测再选）：

- a 继续用 Leaflet，换成高德的瓦片地址：改动最小；但高德官方推荐的是它自己的地图库，直接用瓦片地址是不是在条款允许范围内，要核对。高德瓦片也是图片，能不能拿到高分辨率版本，要实测。
- b 国内这块改用高德自己的地图库（矢量、最清楚）：要和 Leaflet 并存或替换，改动大。

**不变的**：国外照旧用 OSM 和 Nominatim；打包的省级和区县边界继续用来离线点亮；离线时（没网）照样显示打包的轮廓。

## 实现（2026-11-24）

- **服务端**：
  - `server/amap.ts`：高德的坐标查地名（50 米内最近的店、景点作为地名）、地名查地点（行政区排前面）、行政区边界。
  - `server/places.ts`：分派。国内（粗略矩形）先问高德，高德说不是中国、出错或没配 key 就退回 Nominatim；
    搜索两边一起查，高德的排前面，再补 Nominatim 里国外的结果。
  - 新接口 `GET /api/geocode/boundary?id=`：6 位数字是高德的行政区代码，`R` 开头是 OSM 的编号。
    边界简化到约 500 米、坐标留 5 位小数：杭州市 365 个点、约 7 KB。只转发，不存。
  - 新的环境变量 `AMAP_WEB_KEY`。
- **坐标换算**：`shared/gcj02.ts`（前后端共用）。服务端收到高德的坐标先换回 WGS-84，App 里只有 WGS-84。
- **地图**：
  - `src/lib/geo/mapCrs.ts`：一个"先换成 GCJ-02 再投影"的坐标系。地图上所有东西照旧用 WGS-84，
    画在高德底图上自动对齐，点地图拿到的坐标也自动换回来。
  - 高德瓦片分两层：高清底图（512 像素，没有文字）加普通的文字层（256 像素，中文地名）。
    文字层没有高清版，手机上文字会比底图软一点；要完全清楚得换高德自己的地图库（接法 b）。
  - 什么时候用高德：地图停下来时看中心。缩小到 7 级及以下，中心在国内的大致范围里就用高德
    （中心常落在海上、邻国，但这时最要紧的是国内那块清楚）；放大以后用打包的边界数据确认是不是中国。
    在海上等哪儿都不属于的地方，保持现在的底图，不来回切换。
  - 换底图要换坐标系，Leaflet 不支持中途换，所以重建地图，保留位置和缩放。

## 实测（2026-11-24）

- 用真实 key 调用：
  - 坐标查地名：断桥附近得到"杭州西湖风景名胜区 · 杭州市 · 西湖区 · 西湖街道"。
  - 搜"杭州"：杭州市（城市，330100）排第一；搜"西湖区"：杭州的、南昌的都列出来，App 里用查表数据标上省市分开。
- 对齐：雷峰塔在高德里的坐标换成 WGS-84 后加成星星，在高德底图上正好落在"雷峰塔景区"旁边。
- 国外地名的局限：Nominatim 按中文名严格匹配，搜"京都"只出来车站，要写"京都市"。
  "补以前去过的地方"用的是打包的列表，不受影响。
