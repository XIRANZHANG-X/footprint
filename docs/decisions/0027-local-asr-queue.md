# 0027 本机语音识别 + 离线排队整理

- 状态：已定并实现（2026-11-24）。来源：`docs/ideas.md` 一.1（本地语音识别）、六.2（后台任务队列）。
  用户说"全部开始做"，按推荐做。
- 两件事合起来的目标：**没网照样记，有网了自动整理**。

## 1. 用哪个引擎（选 A）

| 备选                                                        | 取舍                                                                             |
| ----------------------------------------------------------- | -------------------------------------------------------------------------------- |
| **A sherpa-onnx 安卓库 + SenseVoice-Small，Capacitor 插件** | **选定**。手机 CPU 原生跑，最快；要写一点 Java；只有安卓 App 有                  |
| B 同一个模型在 WebView 里用 WebAssembly 跑                  | 网页版也能用，但 239 MB 要整个读进 wasm 内存，手机上吃不消；托管要切成 10 块以上 |
| C Whisper-small（transformers.js）                          | 接入最省事；中文不如 SenseVoice，常出繁体、缺标点，逐字生成，慢                  |
| D 继续只用云端                                              | 没网不能录、慢的问题还在                                                         |

策略：App 里默认本机；本机识别出错、而能连上服务端时退回云端。网页版照旧用云端。
"偏好"页里可以改成"云端"（只在有本机模型的 App 里显示）。

## 2. 用哪一版模型（选 2024-07-17 原版）

sherpa-onnx 有两份 SenseVoice int8：

- **2024-07-17**：从 FunAudioLLM/SenseVoice 原版转换。
- 2025-09-09：从 ASLP-lab 的 WSYue-ASR（**粤语微调版**）转换。一开始下的是这份，因为日期新。

在电脑上用和插件一样的设置（2 线程、language auto、ITN 开、greedy）跑了模型自带的测试音频：

| 音频             | 2024-07-17                                              | 2025-09-09（粤语微调）                                   |
| ---------------- | ------------------------------------------------------- | -------------------------------------------------------- |
| zh.wav（5.6 秒） | 开饭时间早上9点至下午5点。（0.23 秒）                   | 放时间早上九点至下午五点（丢了一个字，没标点、没转数字） |
| en.wav（7.2 秒） | The tribal chieftain called for the boy …（正常大小写） | THE TRIVBAL CHIEF THIN CALLED …（全大写、错词）          |
| yue.wav          | 呢几个字都表达唔到我想讲嘅意思。                        | 同样的字，没标点                                         |

加载模型 1.2 秒（电脑上）。普通话是主要场景，选原版。粤语两版一样好。

## 3. 模型放在哪（选 A：打进安装包，不进仓库）

| 备选                                                        | 取舍                                                                |
| ----------------------------------------------------------- | ------------------------------------------------------------------- |
| **A `npm run asr:assets` 下载后放进 `android/`，打进 APK**  | **选定**。装好就能用，第一次也不用等下载；安装包大约多 250 MB       |
| B 安装包里不带，第一次用时从 ModelScope / Hugging Face 下载 | 安装包小；但第一次要下 239 MB，下到一半断网要处理续传，还要校验文件 |
| C 放进仓库                                                  | 仓库大小翻几倍；GitHub 单文件上限 100 MB，放不进去                  |

协议：sherpa-onnx 是 Apache-2.0；SenseVoice 权重是 **FunASR 模型开源协议 1.1**——可以使用、复制、修改、分发，
条件是注明来源和作者、保留模型名（第 2.2 条）。打进 APK 属于分发，所以 `THIRD_PARTY.md` 和 App 的"偏好 → 语音识别"
都写了模型名、作者（阿里巴巴通义实验室 FunAudioLLM）和协议。以后觉得安装包太大，再改成 B。

没有这两个文件的构建（比如 CI 或者删掉了）照样能编译：gradle 里 AAR 是"有才加"，插件发现没有模型就报"不可用"，App 用云端。

## 4. 离线排队整理（选 A）

| 备选                                                                | 取舍                                                               |
| ------------------------------------------------------------------- | ------------------------------------------------------------------ |
| **A 记录上加一个状态 `queued`，能连上服务端时按记录时间一条条整理** | **选定**。不用新表；记录本身就是队列，备份和恢复都自然带上         |
| B 单独一张任务表，地名、向量、区域补算都进去，带重试和退避          | 更通用；但这些现在都已经有"缺了就补"的后台逻辑，单独建表只多了一层 |
| C 保持现状：没网时只存，之后手动点"重新生成"                        | 不用改；用户得记得回来点                                           |

规则：

- 服务端分成三种情况：连不上（`offline`）、在但要口令（`needsToken`）、在但没配 AI（`unavailable`）。
  前两种保存时排队；第三种不排（排了也永远等不到）。
- 连不上时，编辑区的按钮变成"直接保存"和"联网后让 AI 整理"，两种都排队，能连上后分别按"只补标题标签"和"完整整理"做。
- 浏览器发 `online` 事件时重新检查服务端；能用了就一条一条整理（不并发）。整理中途又断网，这条放回队列，剩下的等下次。
- 卡片上显示"等联网后整理"，可以点"不用整理了"取消。
- 不做自动重试服务端报错的记录（比如模型返回乱的）：那种情况多半重试也一样，还是让用户看到错误再点。

## 实现（2026-11-24）

- 安卓：`LocalAsrPlugin.java`（`status`、`transcribe`；模型第一次用时加载，之后留在内存；单独线程；自己读 WAV）。
  `build.gradle`：只打 arm64-v8a 和 armeabi-v7a 的原生库，`.onnx` 不压缩，AAR 有才加。
- 网页：`src/lib/localAsr.ts`（`transcribeAny`），`Composer` 用它；`AsrModeCard` 在偏好页。
- 下载脚本：`scripts/prepare_asr.mjs`，`npm run app:sync` 之前自动跑。
- 队列：`src/lib/enrich.ts` 的 `queueEnrich`、`drainQueue`、`cancelQueued`；`checkAi` 多了 `offline`；`App.tsx` 监听 `online`。

## 验证

- 电脑上用 sherpa-onnx 的 Python 包、同样的设置跑过三段测试音频（见第 2 节）。
- 界面测试 2 个（Playwright）：断网时保存 → 卡片显示"等联网后整理"、没有调用整理接口 → 恢复网络后自动整理出标题；
  排队的记录可以取消。
- 正式安装包能编译（2026-11-24）：331 MB。其中模型 239 MB（不压缩存放，安卓可以直接映射读取），两种 CPU 架构的原生库共约 56 MB。
- **没验证**：手机上的识别速度和加载时间、手机上真实断网再联网的效果。要用户在手机上试。
