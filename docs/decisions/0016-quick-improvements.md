  下面每一点列出备选，标"选定"的是实现了的。

## 背景

`docs/ideas.md` 里挑出的五项，都是改动小、几天内能见效的：

1. 结构化输出
2. 按任务选模型
3. 用量记账
4. 忠实度检查
5. 边界数据挪出主线程

动手前查了百炼文档（2026-11-23）：

- **JSON Object 模式**：qwen3-vl-plus 在非思考模式下支持，提示词里必须出现 "JSON"。
- **JSON Schema 严格模式**：只有 Qwen3.7/3.8 的 Flash、Plus、Max 等支持；请求里带图片时会自动降级成 JSON Object。
- **思考模式默认值**：qwen3-vl-plus 默认不开思考；qwen3.7 系列默认开启，思考的 token 占输出六成以上。
- **价格**（华北 2 北京，单次输入 ≤ 32K token，每百万 token；语音按秒）：

| 模型            | 输入            | 输出   | 严格格式（JSON Schema） |
| --------------- | --------------- | ------ | ----------------------- |
| qwen3-vl-plus   | 1 元            | 10 元  | 否                      |
| qwen3.7-flash   | 0.2 元          | 0.8 元 | 是                      |
| qwen-flash      | 0.15 元         | 1.5 元 | 否                      |
| qwen3-asr-flash | 每秒 0.00022 元 | —      | —                       |

## 1. 结构化输出（选定 A + 修一次）

| 备选                                                                                  | 结论 / 原因                                                                         |
| ------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| **A 带照片用 JSON Object 模式；只有文字时用 JSON Schema 严格模式（格式由 zod 导出）** | **选定**。百炼能给的最强保证；一份 zod 定义同时生成"给模型的格式"和"校验回复的规则" |
| B 函数调用（tools）                                                                   | 一次抽取用不上多轮工具调用，徒增复杂度。留给以后的 Agent                            |
| C 不改，继续从回复文字里找 `{…}`                                                      | 解析失败直接 502，用户只能重试                                                      |

**回复不合格式时（选定：修一次）**：只把那段回复和问题（zod 的报错）发给文字模型，按严格格式重写，**不重发照片**，快而且便宜。
只修一次，再失败照旧报错。

| 修复的备选                 | 不选的原因                         |
| -------------------------- | ---------------------------------- |
| 不自动修                   | 一个字段超长就整条失败，用户要重来 |
| 整个请求重来一遍（带照片） | 慢、贵，而且不一定更好             |

和 0011"花钱的操作都要用户点一下"的关系：修复属于用户刚刚发起的这一次整理，最多多一次、只在失败时发生，
花费是几百个 token 的文字调用。所以算作同一次操作，不另外问。

校验仍然比给模型的格式宽松：类别不认识就归"其他"、标签不是数组就当空。只有标题、正文这种纠正不了的才去修。

## 2. 按任务选模型（选定 A）

| 备选                                                                       | 结论 / 原因                                                           |
| -------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| **A 有照片用 qwen3-vl-plus；纯文字任务用 qwen3.7-flash，明确关掉思考模式** | **选定**。输出价格是看图模型的 1/12，支持严格格式；实测快很多（见下） |
| B qwen-flash                                                               | 更老，不支持严格格式，输出反而更贵                                    |
| C qwen3.7-plus                                                             | 文字更好，但贵 10 倍（限时 8 折后仍贵），默认开思考                   |
| D 全部用看图模型                                                           | 纯文字任务也按看图模型计价，慢                                        |

纯文字任务包括：只写文字的记录的整理、偏好提炼、出行总结、修格式。模型名可以用环境变量 `TEXT_MODEL` 换，不用改代码。

## 3. 用量记账（选定 A）

| 备选                                                                                                                         | 结论 / 原因                                                                         |
| ---------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| **A 服务端把每次调用的用量放进响应头 `X-AI-Usage`；App 每次调用记一行在本机的 `aiCalls` 表，偏好页显示本月、上月和估算的钱** | **选定**。不改响应正文，旧版 App 不受影响；数据只在本机；以后做使用数据看板也用得上 |
| B 服务端记账（存 Cloudflare KV）                                                                                             | 服务端就开始存东西了，和 0002 冲突；多台设备也分不清                                |
| C 只看阿里云控制台                                                                                                           | 看不到每种操作花了多少，也看不到失败和耗时                                          |

- 价格表写在 `src/lib/usage.ts`，注明查看日期，只是估算：没算免费额度、上下文缓存折扣和阶梯价。
- 失败的调用也记（只有次数和耗时）。
- `aiCalls` 进备份：换签名必须重装 App 时数据不丢，旧备份没有它也能导入。
- 数据库 v7。
- 响应头要在 CORS 里显式放行（`exposeHeaders`），App 才读得到。

## 4. 忠实度检查和"不要用的词"（选定 A）

| 备选                                           | 结论 / 原因                                                           |
| ---------------------------------------------- | --------------------------------------------------------------------- |
| **A 只标出来，用户点"去掉这些重写"或"没关系"** | **选定**。符合 0011；用户可能本来就想留着（照片里的菜单上真写着价格） |
| B 发现了就自动重写                             | 花钱的操作没经过用户；照片里真有的价格也会被当成编的                  |
| C 只把禁用词写进提示词，不检查                 | 看不到效果，模型照样可能写                                            |

**检查什么**（`src/lib/faithful.ts`）：

- AI 写的标题、正文里带单位的数量（价格、时长、人数、距离、份数等），原话和地名里没有的。
  中文数字会先换成阿拉伯数字再比，"一个小时"和"1 小时"算同一个。日期不查，拍摄时间是告诉过模型的。
- "添油加醋"的词：一份默认词表（热气腾腾、治愈、岁月静好……），加上学到的和自己加的；原话里自己用了的不算。
- 不查人名、店名：没有可靠的中文实体识别，查了误报太多。

**从修改里学"不要用的词"**：

- 逐字对齐 AI 原稿和改后的版本，找出被删掉的片段。2–6 个字的片段和默认词表作为候选，两头的虚字（的、了、很……）先去掉。
- 一个候选在两次以上的修改里被删掉，就算学到了。删掉的片段"包含"它就算一次：逐字对齐常把相邻的字一起算进去。
- 用户自己写的东西里用过的词不算：所有原话，加上每次改后的版本。
- "改用自己写的"是整篇不要，不代表哪个词不好，不参与统计。

整理时把这些词告诉模型（`avoidWords`），整理完再检查一遍。偏好页列出学到的词，可以划掉、恢复，也可以自己加。
用户改过标题或正文、或者改用自己写的正文以后，提醒就清掉。

## 5. 边界数据挪出主线程（选定 A）

| 备选                                                             | 结论 / 原因                                            |
| ---------------------------------------------------------------- | ------------------------------------------------------ |
| **A 后台线程 + 坐标改成整数差值编码 + 离线底图单独一份精简轮廓** | **选定**。不加依赖，文件小了近一半，主线程不再碰大文件 |
| B 只挪到后台线程，格式不变                                       | 能解决卡顿，但文件大、内存占用多                       |
| C 二进制格式（类型化数组）                                       | 最小最快，但不好查看，代码更多；现在的大小已经够用     |
| D TopoJSON                                                       | 要加两个依赖（编码、解码），收益和 A 差不多            |

文件大小：

| 文件               | 原来   | 现在   |
| ------------------ | ------ | ------ |
| 全球省州           | 9.7 MB | 5.4 MB |
| 中国区县           | 2.4 MB | 1.3 MB |
| 离线底图轮廓（新） | —      | 2.0 MB |

- 后台线程（`geo.worker.ts`）负责读文件、解码、判断点在哪个区域；地图点亮时只把用得到的几个形状传回界面。
- 格式版本 2，`GEO_VERSION` 一起改成 2，旧记录的所在区域会在后台重算一遍。
- 生成脚本按 `public/geo/format.txt` 判断要不要重新生成，换格式时不用手动加 `--force`。

## 验证

- 测试从 148 个增加到 171 个，全部通过。新增覆盖：
  - 服务端：两种结构化输出模式、修一次（不重发照片）和修不好时报错、用量响应头和 CORS、按任务选模型、`avoidWords` 进提示词。
  - 前端：数量识别、标记、学词、费用估算、备份带用量、边界解码。
- 浏览器里用假数据验证过：
  - 卡片上的提醒；点"去掉这些重写"后，请求带上了被标出的和学到的词，新正文干净，提醒消失，这次调用记进了用量。
  - 偏好页"不要用的词"可以划掉、恢复、添加；"AI 用量"显示的数字和种子数据一致；375 像素宽没有横向滚动。
  - 区域在后台线程里算出，界面线程没有下载大文件；地图点亮正常；离线轮廓 21 毫秒读完。
  - 生产构建：新的后台线程 1.8 KB，首屏代码 462 KB（预算 500 KB）。
- 用户同意后，用 .env 里的 key 真实调用了 4 次（2026-11-24），百炼全部接受新参数：

| 调用                                         | 耗时   | 输入 / 输出 token |
| -------------------------------------------- | ------ | ----------------- |
| 看图整理（qwen3-vl-plus，JSON Object）       | 5.3 秒 | 461 / 91          |
| 只写文字的整理（qwen3.7-flash，JSON Schema） | 1.9 秒 | 365 / 120         |

- 要留意：同一句原话，qwen3.7-flash 写的正文有点别扭（"因为想吃的牛肉面，前面排了整整一个小时"），
  看图模型写得平实。只有一个样本，先不换；用一阵子觉得只写文字的记录正文不好，把 `TEXT_MODEL` 换成 qwen3.7-plus。
