# 0020 看得见的路线（向 Polarsteps 借鉴的第 1 批）

- 状态：已定并实现（2026-11-24）。来源：`docs/polarsteps.md` 第五节第 1、10 条和第四节 A。
  用户定的：第 5 条（家自己设）、第 6 条（列表 + 搜索 + 多选 + 手填）、第 7 条（自动打勾；"想去"和"去过"是两张单子）。
  第 2 条（远距离画弧线）用户提出"一直定位、按拍照时间去轨迹里找位置"，归到第 2 批，这一批先按距离画。
  第 6 条"国内城市怎么点亮"随决策 0021（国内换高德）解决：边界从高德取。

## 现状（动手前查的）

- **地图上已经有连线**，但有三个问题：
  - 只在放大到 9 级以上才画；
  - 连的是搜索和筛选之后剩下的记录；
  - 远距离的一段也是直线，没有弧线。
- **统计**：首页一行（多少条记录、几个城市、几次出行、几个第一次）；回顾页按月、按年。没有国家数、里程、离家最远。
- **地名搜索**：结果只有名称、地址、坐标。
  - 其实 Nominatim（jsonv2 格式）还返回了地点类型（城市、省、国家、景点……）、范围框、国家代码、OpenStreetMap 编号，只是服务端没往外传。
  - 用编号还能取到这个地方的边界。实测（2026-11-24）：搜"杭州"，第一个结果是城市一级的行政边界，
    取边界并简化到约 500 米精度，是 449 个点、约 12 KB。
- **国内没有地级市边界**：
  - 打包在 App 里的数据只有省级（Natural Earth）和区县（geoBoundaries，2017 年，2391 个），没有地级市（0014 补记）。
  - 区县边界的名字是拼音（如 "Mohexian"），对不上中文城市名。

## 1. 路线怎么连（推荐 A）

| 备选                                                                         | 取舍                                                                                 |
| ---------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| **A 每次出行按时间连全部有位置的记录；有搜索或筛选时不画；任何缩放级别都画** | **推荐**。缩小到全国、全世界时，看得见一次出行跨过哪些地方，这正是这一批要的"看得见" |
| B 照现在：连筛选后剩下的记录                                                 | 搜"火锅"时把几家火锅店连起来，看着像一条路线，其实不是                               |
| C 所有记录按时间连成一条                                                     | 两次出行之间回了家，中间没有记录，连起来的线是假的                                   |
| D 只画选中的那次出行                                                         | 要先选才看得到；以后可以加"只看这次"，和 A 不冲突                                    |

- 和 Polarsteps 一样按出行分开连。它的一次出行从家出发；我们不知道家在哪，所以不画"从家出发"那一段（第 5 条的"家"只到城市一级，不够画线）。
- 同一个地方（100 米内）连着的几条记录只算一个点。

## 2. 远距离的一段怎么画（推荐 A，等用户回复）

**Polarsteps 怎么处理**：

- 它的 App 一直在后台定位，每隔一会儿就记一个点（地图上的小白点），一段路上有很多点。
  - 坐火车、开车时，沿路每隔一会儿就有一个点，连起来就是沿着路走的折线。
  - 坐飞机时，手机在天上不记点。于是"起飞前最后一个点"和"落地后第一个点"之间是一个大空档：距离远、隔的时间短，算出来速度很快。
- 它的规则就是抓这个空档：两点相距 ≥ 200 公里且平均时速 > 100 公里，或者相距 > 1500 公里，就判成飞机，画成弧线。

**在我们这里的问题**：我们没有后台定位，点只来自照片。两张照片之间常常隔好几个小时（等车、候机、先去酒店），
算出来的平均速度和真正的交通工具对不上，两个方向都会判错：

| 例子                                                                                    | 平均时速             | 按它的规则判成 | 实际 |
| --------------------------------------------------------------------------------------- | -------------------- | -------------- | ---- |
| 上午 8 点在上海拍最后一张，坐 5 小时高铁，晚上 7 点在北京拍第一张（约 1200 公里）       | 1200 ÷ 11 ≈ 110 公里 | 飞机           | 高铁 |
| 上午 9 点在杭州拍最后一张，坐飞机去厦门，晚上 8 点拍第一张（约 600 公里，含候机、打车） | 600 ÷ 11 ≈ 55 公里   | 地面交通       | 飞机 |

规则本身没问题，问题是我们的点太稀。

**用户的想法（2026-11-24）**：既然要做一直定位（第 2 批），照片的位置就可以按拍摄时间到轨迹里去找，
不用依赖照片自带的定位；点密了，Polarsteps 的规则也就能用了。这是对的，记进第 2 批：
轨迹给照片补位置，还能顺带解决"微信传过来的照片没有定位"（0003 的老问题）。
限制：只对开着记录时拍的照片有效；以前的照片、iPhone 网页版，仍然只能靠照片自带的定位。所以建议这一批先不判断交通工具，只按距离画（A）；
第 2 批有了后台定位、点变密以后，再用它的规则，并且让你手动改交通方式。

| 备选                                                                                           | 取舍                                                                                                                          |
| ---------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| **A 超过 300 公里的一段画成虚线弧线，不区分飞机还是高铁**                                      | **推荐**。我们只有照片的时间和位置，算出来的速度不可靠（见下）；弧线只表示"这一段是跳过去的，中间没记录"                      |
| B 照搬 Polarsteps 的规则：相距 ≥ 200 公里且平均时速 > 100 公里，或相距 > 1500 公里，画成飞行线 | 它的规则建立在轨迹点很密的前提上。我们的两张照片可能隔好几个小时：上海到北京坐高铁，照片隔 6 小时，平均时速 200，会被判成飞机 |
| C 都画直线                                                                                     | 跨省、出国的长直线压住一大片地图，看不出哪段是"跳"过去的                                                                      |

- **弯的方向**：往前进方向的左边弯，这样去程和回程两条线不会叠在一起。
- **跨越 180 度经线**（比如飞美国）：往近的那边画，不绕地球一圈。
- 第 2 批有了轨迹和"交通方式"以后，再分飞机、火车、开车。

## 3. 线的样子（不用选，按 0010 的配色定）

- **颜色**：香芋紫加深一档。0010 规定香芋紫表示"出行分组"，路线属于一次出行。
  下面垫一层奶油白的描边，在各种颜色的地图瓦片上都看得清。
- **线型**：普通的一段画实线，远距离的一段画虚线弧线。
- **线头**：直角，不用圆头，保持像素感。

| 备选                                                                 | 取舍                                                               |

| B 首页那一行统计加长                                                 | 320 像素宽放不下                                                   |

**卡片内容**：

- 国家和地区 N 个，点开看名单。
- 城市 N 个。
- 总里程：约 X 公里，按记录之间的直线算，注明"实际走的路更长"。
- 离家最远：某地，约 Y 公里。
- 补的地方 N 个（第 6 条）。

**出行标题**：例如"11月3日 – 11月5日 · 3 天 · 8 条 · 约 120 公里"，不到 1 公里就不写。

**不显示国旗**：Windows 上的浏览器不显示国旗表情，只会显示两个字母。只写国名（浏览器自带中文国名，不用另加数据）。

## 6. 补以前去过的地方（已定：列表 + 搜索 + 多选 + 手填）

刚开始用的人，地图是空的，没有成就感。Polarsteps 能手动补"以前去过的国家"。

| 备选                                                           | 取舍                                                                                  |
| -------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| A 搜地名补，地图上画出那个地方的真实边界（来自 OpenStreetMap） | 我原来推荐的。一次只能搜一个地方，补十几个城市要搜十几次                              |
| **B' 列表 + 搜索框 + 多选，列表里没有的可以直接填名字**        | **用户提出并选定**。打几个字就筛出来，一次勾好几个；列表数据 App 里本来就有，不用联网 |
| B 只从列表选（离线），没有搜索和手填                           | 列表有几千项，不搜找不到                                                              |
| C 只能补国家                                                   | 国内旅行为主的人用处不大                                                              |

**列表里有什么**（都已经打包在 App 里，不用联网）：

- 国家和地区：约 250 个，中文名浏览器自带。
- 国内的省、地级市、区县：查表数据里共 3420 个（0014 借的 modood 数据）。
- 国外的省、州：边界数据里有中文名的 4500 多个。

**怎么用**：

- 打开"补以前去过的地方"，上面一个搜索框，下面是列表。
- 打几个字就筛出来，例如打"杭"出现"杭州市 · 浙江省""杭锦旗 · 鄂尔多斯市"。
- 每项前面一个勾，可以勾好几个，最后点"加入 3 个"。
- 列表里没有的（比如"稻城亚丁"这种景区），点"直接填名字"自己写。

**怎么算进统计**：

- 国家数：直接选的国家，加上选的省、市、区县所在的国家。
- 城市数：选的地级市；选区县算它所属的市；北京、上海这类直辖市选省一级也算城市；国外的省州算城市（和现在记录的算法一致）。
- 只计入国家数、城市数和点亮，不计入里程和"第一次"。
- 进备份，可以删。

**地图上怎么显示**：

- 用更浅的颜色加虚线边，提示是"补的"，和真的记录区分开。
- 国家、国内的省、国外的省州：App 里有边界，直接点亮。
- **国内的地级市、区县，和手填的地方**：App 里没有它们的边界（见"现状"），还要再定一个小问题：

| 备选                                                                                    | 取舍                                                             |
| --------------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| **a 有网时自动查一次它的真实边界（OpenStreetMap），查到就点亮；没网或查不到，先只计数** | **推荐**。"去过杭州"就亮杭州这一块；要改服务端（见下）并重新部署 |
| b 只计数，地图上不显示                                                                  | 不用改服务端；但补了一堆城市，地图上还是空的，达不到"看得见"     |
| c 把所在的整个省淡淡点亮                                                                | 不用联网；但"去过杭州"亮了整个浙江，看着像去过温州、丽水         |

**a 要改的服务端**：

- 搜索结果多带四样东西：类型（城市、区县、景区……）、范围框、国家代码、OpenStreetMap 编号；
- 加一个按编号取边界的接口，简化到约 500 米精度（杭州约 12 KB）。
- 两处都只是转发 Nominatim，不存任何东西；旧版 App 不认识新字段，照常工作。
- 第 7 条的"想去的地方"判断去没去过，也用这套。

## 7. 想去的地方（推荐 A，等用户回复）

**这是什么**：一个"以后想去"的清单，和 Polarsteps 的"收藏"、计划里的目的地是一类东西。举个例子：

1. 你在小红书上看到大理有一家咖啡馆想去，就在 App 里搜到它，加进"想去"清单（或者在地图上那个位置长按）。地图上那里出现一颗星星。
2. 过了几个月你真的去了，在那里拍照、记了一条。
3. App 发现这条记录的位置就在那家咖啡馆旁边，星星变成"去过了 ✓"，旁边写着"11 月 3 日去的"，点一下跳到那条记录。

要定的是第 3 步：App 自己发现、自动打勾（A），还是你自己回来手动打勾（B）。

**用户定的（2026-11-24）**：自动打勾。"想去"和"去过"是两张单子，同一个地方可以两边都有：
去过西湖、还想再去，西湖就既在"去过"（以前的记录）里，也在"想去"里。
只有再去一次（加进清单之后的新记录）才算实现，这时西湖从"想去"里移走，"去过"里多一条记录。
移走的收进一个折起来的"实现了"小区，判错了可以拿回来。

**放哪（推荐 A）**：

| 备选                                                           | 取舍                                               |
| -------------------------------------------------------------- | -------------------------------------------------- |
| **A 地图页上一个"想去"按钮，点开是清单；地图上用像素星星标出** | **推荐**。和地图在一起，看得见离已经去过的地方多远 |
| B 新加第 6 个页签                                              | 375 像素宽放不下 6 个页签                          |
| C 放进回顾页                                                   | 回顾是往回看的，清单是往前看的                     |

**怎么加**：

- 搜地名（和第 6 条用同一套搜索，带边界）。
- 在地图上长按一个点（没网也能加，名字自己填）。
- 每个地方可以写一句备注（"想吃那家面"）。

**"去过了"怎么判断（推荐 A）**：

| 备选                                                                     | 取舍                               |
| ------------------------------------------------------------------------ | ---------------------------------- |
| **A 自动：加进清单之后拍的记录落在那个地方里，就标"去过了"，可以手动改** | **推荐**。不用操作，去了自然就打勾 |
| B 只能手动标                                                             | 要记得回来打勾                     |

- **"落在那个地方里"**：有边界的（城市、景区）按边界判断；没有边界的（小店、长按加的点）按 200 米以内。
- **只算"加进清单之后"的记录**：已经去过、还想再去的地方，加进来不该马上算完成。
- **标成"去过了"**：显示是哪天哪条记录，点一下跳过去；那条记录的卡片上多一个"★ 想去的地方"标签。

**数据**：新表 `wishes`（数据库 v8），进备份。

## 不在这一批做的

- 交通方式和图标、按速度猜交通方式：第 2 批，要先有轨迹。
- 贴合道路：要用路径规划服务，国内的数据质量和使用条款要先查。
- 路线回放、短视频：第 5 批。

## 实现（2026-11-24）

- **路线**：`src/lib/route.ts`（按时间连、同一地方合并、超过 300 公里画弧线、算里程）；地图上的 `RouteLayer`。
  有搜索或筛选时不画。时间线上每次出行的标题加了里程（`tripLabel.ts`）。
- **足迹总览**：`src/lib/footprint.ts` 和 `FootprintCard.tsx`，在地图页顶部。常驻城市存在设置表（`home`），用地名搜索设。
- **补以前去过的地方**：`VisitedPicker.tsx`。
  - 列表：国家约 250 个（中英文都能搜）、全球省州 4586 个（后台线程只传名字）、国内省市县 3420 个。
  - 国内的市、区县加进来以后联网取高德的边界；取不到（没网、没口令）就先只计数，提示用户。
  - 自己填的名字联网搜一次，补上国家、城市和边界。
  - 地图上用浅色加虚线边（`AddedLayer`）。
- **想去的地方**：`WishList.tsx`、`src/lib/wishes.ts`、`src/lib/addWish.ts`。
  - 搜地名加，或在地图上长按（电脑上右键）加。城市、区县这类有边界的，按边界判断去没去过；其余按 200 米。
  - 只算加进清单之后的记录；实现了的收进折起来的"实现了"，可以"拿回来"（从现在起重新算）。
  - 地图上用柠檬黄的像素星星；实现它的那条记录卡片上有"★ 想去的地方"。
- **数据库 v8**：新表 `wishes`、`visited`，都进备份；旧备份照常导入。
