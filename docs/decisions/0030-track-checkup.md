# 0030 记录体检：先测出后台轨迹的耗电和断档

- 状态：已定并实现（2026-11-25）。来源：`docs/tracking-polish.md` 第三节第 1、2 条。用户说"先做体检"。
- 目的：后台轨迹的耗电和稳定性是用户认为最关键的两件事，但现在**完全没有数据**。先让 App 自己记下来，
  用户出门一两天就知道：一天耗多少电、有没有被系统停掉、断了多久、点从哪来。后面的改动（停下来关 GPS、自动恢复、
  错点处理）都按这些数据决定。

## 1. 怎么测（选 A）

| 备选                                                        | 取舍                                                                             |
| ----------------------------------------------------------- | -------------------------------------------------------------------------------- |
| **A App 自己记心跳，回到 App 时算**                         | **选定**。不用电脑，日常出门就能攒数据；断档能直接提示用户                       |
| B 用电脑抓系统耗电报告（adb bugreport + Battery Historian） | 最准，能分清谁在耗电；但要连电脑、会用工具，只适合调试时做一两次。以后需要时再做 |

## 2. 记什么

记录路线时，和轨迹点写在同一个暂存文件里（回到 App 时一起取走）：

- **start**：开始，**stop**：用户点了停止，**lost**：被系统停了，**hb**：每 15 分钟一条心跳。
- 每条都带：时间、电量、是否在充电、**屏幕亮没亮**、精确还是省电、**GPS 和网络定位这台手机有没有、开没开**。
- 只存在这台手机里（`trackEvents` 表，数据库 v13），不同步、不进备份。

## 3. 怎么发现"被系统停了"

| 备选                                                                                             | 取舍                                                                                       |
| ------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------ |
| **A 系统闹钟（低电耗模式下也会响）每 15 分钟一次；响的时候服务不在、用户又没点停止，就是被停了** | **选定**。进程被杀后闹钟照样会响（系统会重新拉起进程跑这个接收器），能在当时就发现并发通知 |
| B 只在回到 App 时检查                                                                            | 简单，但要等用户自己打开才知道；中间那段已经丢了                                           |

- 两种都做：闹钟发现时发一条通知"路线记录被系统停了"；打开 App 时也检查一次（服务不在但记着"在记录"）。
- 心跳用不精确的闹钟（精确闹钟要额外权限），系统会推迟，所以**超过 45 分钟没有任何动静（心跳或轨迹点）才算断档**。
- 被手机管家"强行停止"时闹钟也会被清掉，这种情况只能等打开 App 时发现。
- 现在只发现、不自动恢复：自动恢复要"始终允许定位"权限，是下一步、要用户决定（`tracking-polish.md` 三.2）。

## 4. 耗电怎么算

- 手机给的电量是**整机的**，包括屏幕和别的 App。所以只算"**相邻两条心跳都在锁屏、都没充电、中间没断**"的时段，
  这时手机基本只剩后台任务，最接近后台记录的消耗。还是会包含手机自己的待机耗电，界面上写明。
- 锁屏时段不到 1 小时不给数（电量只精确到 1%）。
- 目标（对标 Polarsteps 自称的一天约 4%）：省电模式一天 5% 以内，精确模式 15% 以内。超了标黄。

## 5. 界面

- 地图页"记录路线"卡片下面一个可展开的"记录体检"：最近 3 次记录，每次列出断档、被停的时间、锁屏耗电、
  点的数量和来源（GPS / 网络 / 借别的 App）、精度中位数，以及"这台手机没有网络定位"之类的问题。
- 有断档或被停过时，**按手机品牌**（小米、华为/荣耀、OPPO/一加/realme、vivo/iQOO、三星、其他）给出放行后台的设置路径，
  再加一个打开系统电池优化设置的按钮。路径参考各品牌常见的设置名称，系统版本不同会略有出入。

## 实现（2026-11-25）

- 安卓：`TrackHealth.java`（电量、充电、屏幕、定位来源、事件、闹钟、被停通知）、`HeartbeatReceiver.java`（闹钟接收器，清单里注册）；
  `TrackerService` 记 start / stop / lost、动起来时顺带补心跳；`TrackerPlugin` 打开 App 时检查被停、返回手机品牌。
- 网页：`src/lib/trackSync.ts` 把事件和点分开存；`src/lib/trackHealth.ts`（分段、断档、耗电、来源、结论，纯函数）；
  `TrackHealthPanel.tsx`。

## 验证

- 单元测试 5 个：按 start 分段并知道每次怎么结束的；心跳和轨迹点一起算断档；被停的时间取最后一次确认活着；
  耗电只算锁屏、没充电的时段；没有网络定位、一直没点时给出提示；一切正常时显示"没有断档"。
- 界面测试 1 个：用假的安卓桥冒充 App，交出一段有 75 分钟断档、最后被系统停掉的记录，检查体检显示的每一项和小米的设置路径。
- 安卓代码能编译。
- **没验证**：真机上闹钟实际多久响一次、被停后能不能发出通知、锁屏耗电的数字准不准。这正是要用户出门实测的。
