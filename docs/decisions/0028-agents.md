# 0028 两个带工具的 Agent：问问我的足迹、帮我找地点

- 状态：已定并实现（2026-11-24）。来源：`docs/ideas.md` 三.1、四.1、四.2、四.4、四.5。
  用户说"全部开始做"，按推荐做。
- 两个 Agent 共用一套做法。区别只在于给模型哪些工具，以及最后交回什么。

## 1. 架构：模型在服务端，工具在手机上跑（选 A）

| 备选                                                                                   | 取舍                                                                                 |
| -------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| **A 服务端只转发一轮对话；模型要调用工具时把调用交回 App，App 查本机数据后再发下一轮** | **选定**。数据留在手机上，服务端仍然什么都不存（0002）；每一步查了什么都能摆给用户看 |
| B 把记录传到服务端，在服务端跑完整个循环                                               | 一次请求就完；但每问一次都要把全部记录交出去，违反 0002                              |
| C 不用工具，把全部记录塞进上下文（ideas 三.1 的 C）                                    | 最简单；记录多了又贵又慢，"去了几次"这种数数的问题模型也常数错                       |

- 接口：`POST /api/agent`，请求里写明是哪个 Agent（`ask` 或 `locate`）和到目前为止的对话。
  **系统提示词和工具列表由服务端按 Agent 种类决定，App 不能自己传**，防止口令泄露后被拿去当通用聊天接口。
- 模型：文字模型 qwen3.7-flash，不开思考模式，用 OpenAI 兼容的函数调用（`tools`）。
- 收尾也通过工具：问答用 `answer`（正文 + 引用了哪几条记录），找地点用 `propose`（候选 + 证据）。
  这符合"用工具调用，不解析输出格式"的原则：App 拿到的是校验过的参数，不用从文字里找 JSON。

## 2. 安全约束（ideas 四.4）

- **步数上限**：一次最多 6 轮模型调用；到上限还没收尾，就停下来，给出"没查完"和已经查到的东西。
- **大小上限**：服务端只接受 user / assistant / tool 三种消息，总长度不超过 4 万字；每个工具结果在 App 里截到 4000 字。
- **工具都是只读的**。会改记录的只有最后一步，而且必须用户点了才写（找地点）。
- **工具结果一律当数据**：照片里抄下来的招牌、记录正文里可能有"忽略之前的指令"这种字。
  系统提示词里写明这一点，工具结果外面包一层标明"以下是数据"。
- **证据要对得上真实的工具结果**（沿用 geo-sleuth 的规则）：找地点的候选只能引用工具结果里的编号；
  编不出来的编号 App 会丢掉。问答引用的记录编号也一样，只保留真的查到过的。

## 3. 问问我的足迹（ideas 三.1 + 四.2）

工具（都在手机上查本机数据库）：

| 工具             | 做什么                                                                                                    |
| ---------------- | --------------------------------------------------------------------------------------------------------- |
| `search_records` | 按关键词、城市、类别、时间段找记录。关键词先按字面匹配，不够时再用本机的语义向量（0014 3A）补；最多 12 条 |
| `stats`          | 按城市、类别、年份或月份数数：几条记录、几天，第一次和最近一次是哪天                                      |
| `get_record`     | 看一条记录的全文（自己写的和 AI 写的）                                                                    |
| `answer`         | 收尾：回答 + 引用的记录                                                                                   |

- 发给模型的只有检索到的那几条记录的文字：日期、标题、地名、城市、类别、标签、正文的前 120 字。**不发坐标，不发照片。**
- 界面：时间线的搜索框下面有一个"问问我的足迹"。问完显示回答、它查了什么（"查了：杭州 · 美食 · 2025 年"），
  引用的记录直接列在下面，可以点开。
- 统计问题（"去了几次""哪个月最多"）交给 `stats` 算，不让模型自己数。

## 4. 帮我找地点（ideas 四.1，缩小版的 geo-sleuth）

给"待定位"的记录用，在"补地点"里点"让 AI 找找看"。工具：

| 工具              | 做什么                                                                                                   |
| ----------------- | -------------------------------------------------------------------------------------------------------- |
| `record_clues`    | 这条记录的文字：原话、AI 写的标题和正文、AI 从照片里猜的地名、照片里抄下的电话和车牌，以及查表得出的城市 |
| `same_day_places` | 同一天有定位的其他记录：时间、地名                                                                       |
| `past_places`     | 以前去过、名字里有某个词的地方                                                                           |
| `search_place`    | 按名字查地点（服务端的高德 / Nominatim，和"补地点"的搜索一样），最多 5 个                                |
| `propose`         | 收尾：最多 3 个候选，每个引用一个工具结果里的编号，附证据                                                |

- 每个可以选的地点在工具结果里都有编号（`d1` 当天、`p2` 以前去过、`s1-3` 搜索结果）。`propose` 只能用这些编号，
  所以候选的坐标一定来自真实的查询，不会是模型编的。
- 候选显示证据（"电话区号 0571 → 杭州；同一天 14:00 在西湖"），用户点了才写进记录。
- 不重新看照片：照片里的线索在整理时已经抄下来了（0013、0014），这里只用文字，便宜。

## 5. 运行记录和评估（ideas 四.5）

- 每次调用照常记进"AI 用量"（种类 `agent`）。每一步调用了什么工具、用了多久，只在这次的界面上显示，不另外存。
- 单元测试用固定的假数据测每个工具；界面测试用假的模型回复走完整个循环（包括引用了不存在的编号会被丢掉）。
- 试跑脚本 `scripts/eval_agents.ts`：写死的 9 条假记录，4 个问题 + 1 次找地点，用真实模型，打印每一步和费用。
  以后要正式评估（20 个问题和标准答案，比较"检索"和"全塞进去"），在它的基础上加。

## 实现（2026-11-24）

- 共用：`shared/agents.ts`（工具参数、对话格式、上限）、`server/app.ts` 的 `/api/agent`、`server/prompts.ts` 的 `agentSystem`、
  `src/lib/agents/run.ts`（循环）。
- 问问我的足迹：`src/lib/agents/askTools.ts`（工具，纯函数）、`ask.ts`；界面 `AskPanel.tsx`，在时间线最上面，能连上 AI 时显示。
- 帮我找地点：`src/lib/agents/locateTools.ts`、`locate.ts`；界面 `LocateAgent.tsx`，在"补地点"里。

## 验证

- 单元测试 9 个：按词、城市、时间段找，语义结果只补范围内的；按城市、月份数数；月底、日期边界；
  循环把工具结果标成数据发回去、参数不对告诉模型而不是崩、到步数上限停下、长结果截断；找地点只留下对得上的候选。
- 服务端测试 3 个：系统提示词和工具列表由服务端定，编出来的工具名丢掉；App 传 system 消息、步数超限、太长、未知种类都拒绝。
- 界面测试 2 个（假模型）：问一句 → 显示查了什么、回答和引用的记录，没查到过的编号不显示，发出去的只有查到的那条；
  找地点 → 显示候选和依据，编出来的编号不显示，点了写进记录。
- **真实模型试跑**（2026-11-24，qwen3.7-flash，`scripts/eval_agents.ts`）：12 次调用，16877 tokens，约 ¥0.004。
  - "我去过几个城市？"用 `stats` 答对（杭州、上海）。
  - "去年在杭州吃过哪些面？"把"去年"换成 2025-01-01～2025-12-31，找到两碗面。
  - "第一次去上海是哪天？"先按年份统计，再查那一天，答对 2024-05-01。
  - "在上海看过什么展？"答对。
  - 找地点：看线索 → 看当天 → 搜"杭州 知味观"，第一候选是湖滨总店，依据写了区号、原话和当天的行程。
    另外两个候选是同一地址的其他门面，有点多余，但都对得上真实搜索结果。
- 没验证：手机上的效果；记录多（几百条）时检索够不够用。

## 不做

- 多轮追问（问完接着问）：先只做一问一答，以后看用得多不多。
- 照片内容搜索（ideas 三.3）、主动发现出行（四.3）。
