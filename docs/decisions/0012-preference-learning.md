# 0012 学习用户的修改习惯；自己写的和 AI 写的二选一

- 状态：已定（2026-11-10）

## 背景

决策 0001 的第 3 阶段是"学习用户的修改习惯，让用户需要改的地方越来越少"。
实测里用户也觉得 AI 正文太夸张（0006）。这两件事是同一个问题：AI 不知道这个用户喜欢怎么写。

现状有一个缺口：每条记录只存"AI 最新一稿"和"用户现在的版本"，点一次"重新生成"，
上一稿和那次修改就被覆盖了，没法拿来学习。

## 决定

### 1. 先存下每一次修改

新增一张"修改记录"表：每次保存时存下 AI 原稿、用户改后的版本、时间，以及改动了多少字。
用户放弃 AI 版本、改用自己写的，也算一条记录（这是最强的"不满意"信号）。
修改记录只存在本机，会进备份。

### 2. 怎么用：先"偏好说明 + 例子"，用久了以后只用"偏好说明"

- 偏好说明：一段短文字，描述这个用户喜欢怎么写（例如"语气平实，不加我没说过的形容"）。
  用户可以在"我的偏好"页面查看和修改。每次整理都带上它。
- 例子：最近 1–2 次"AI 原稿 → 用户改后"，放进提示词，相当于少样本提示。
- 早期两样都带（偏好说明还很薄，例子能补上最新的习惯）；
  偏好说明经过几轮自动总结、用户确认后已经稳定，就不再带例子，请求更短、更便宜。
- 自动总结：每攒够若干次修改，让模型提出一版新的偏好说明，用户确认后才生效。

衡量指标：每次保存时用户改了多少字，这个数字应该随时间下降。

| 备选                 | 不选的原因                                                 |
| -------------------- | ---------------------------------------------------------- |
| 一直只带例子         | 每次请求都更长、更贵、更慢；只记得最近几次，学不到长期规律 |
| 一开始就只用偏好说明 | 攒够修改之前说明是空的，没有效果；用户选了先带例子过渡     |
| 微调模型             | 个人用量的数据太少，成本和工程量都不合适                   |

### 3. 自己写的和 AI 写的，二选一

选完照片、写完内容后，用户有两个选择：

- 直接保存：就用自己写的内容。
- 让 AI 整理：生成一版新的。生成后，自己写的和 AI 写的同时显示，两边都可以改，最后选一个保存。

没选中的那一版也留着，之后可以换回来。

### 4. 用自己写的内容时，AI 只补标题、类别和标签

"直接保存"后正文一个字不动，就是用户写的；AI 在后台只生成标题、类别和标签。
没有网络或 AI 失败时，记录照样存好，只是暂时没有标题和标签，之后可以重试。

| 备选                       | 不选的原因                                                       |
| -------------------------- | ---------------------------------------------------------------- |
| 标题和标签都不要           | 以后的搜索、筛选、统计要靠类别和标签；卡片和分享图没有标题不好看 |
| 保存后留一个按钮，想补再点 | 多一步操作，大概率会忘了点（用户 2026-11-10 选了自动补）         |

### 5. 不做"平实 / 活泼"开关

默认提示词直接改成平实：只用用户的原话和照片里看得见的内容，不补充用户没说过的形容。
想要别的风格，在"我的偏好"里写一句即可。

| 备选                                 | 不选的原因                                                                     |
| ------------------------------------ | ------------------------------------------------------------------------------ |
| 每次整理前选"平实 / 活泼"            | 和偏好说明是两套机制，会互相冲突；用户改稿时也分不清是风格选错了还是 AI 没学会 |
| 在偏好页放两个预设按钮，点一下填进去 | 现在只有"太夸张"这一个不满，改对默认值就够；以后需要可以再加，不用返工         |

### 6. 什么时候自动总结，什么时候不再带例子

- 自动总结：每攒够 5 次修改，让模型提出一版新的偏好说明，和现在的并排显示。
  用户确认才生效，也可以改几个字再确认，或者忽略。
- 停用例子看效果：最近 5 次整理，用户平均改动的字数低于正文的 10%，就不再带例子；
  之后如果升回 20% 以上，自动恢复。
- "我的偏好"页面里有一个"带上最近的例子"开关，用户可以手动覆盖上面的自动判断，页面上也显示当前是哪种状态。
- 这些数字（5 次、10%、20%、带几个例子）都写成配置，不写死在代码里。

| 备选                         | 不选的原因                                             |
| ---------------------------- | ------------------------------------------------------ |
| 每 3 次总结                  | 样本太少，容易把偶然的一次修改当成习惯；提示太频繁     |
| 每 10 次总结                 | 要等一个月以上才有第一版                               |
| 确认过固定几版说明后停用例子 | 不看实际效果；习惯变了或说明总结歪了，没有办法自动恢复 |
