# 0022 自动记录路线（向 Polarsteps 借鉴的第 2 批；改 0003）

- 状态：已定并实现（2026-11-24）。用户说"全部开始做"，各项按推荐做。
  方案的来龙去脉见 `docs/polarsteps.md` 第一节、0020 第 2 条里用户的想法。
- **改 0003**：0003 当时"不做后台轨迹"，理由是耗电、隐私敏感、必须是原生 App。现在 App 已经是原生外壳（0009），
  用户明确要做；耗电用"出行时手动开、省电档"控制，隐私用"只存在手机里 + 隐私区"控制。

## 1. 怎么在后台记（推荐 A）

| 备选                                                              | 取舍                                                                                                      |
| ----------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| **A 自己写安卓前台服务，用系统自带的定位接口（LocationManager）** | **选定**。没有谷歌服务的国产手机也能用；不加依赖；记下的点先写进 App 自己的文件，WebView 被系统关掉也不丢 |
| B 社区插件 `@capacitor-community/background-geolocation`          | 省事；但要确认它在没有谷歌服务的手机上能不能用，点只回调给网页，网页被关掉就丢                            |
| C 商业插件（Transistor）                                          | 功能最全，安卓正式版要付费授权                                                                            |
| D 只在 App 打开时用网页的定位接口记                               | 不用写原生代码，但锁屏就停，等于没做                                                                      |

- **什么时候记**：你在 App 里点"开始记录路线"，到点"停止"为止（Polarsteps 也是按出行开）。
  记录时通知栏常驻一条"足迹手账正在记录路线"，这是安卓的规定，也让你知道它在记。
- **权限**：只要"使用期间允许定位"和通知。服务是 App 在前台时开的，之后锁屏、切到别的 App 照样能记，
  **不需要**"始终允许"这个更敏感的权限。代价：手机重启后不会自己恢复，要再点一次开始。
- **两档**：
  - 省电（默认）：网络定位优先，最少隔 3 分钟或走了 100 米才记一个点；
  - 精确：GPS，最少隔 30 秒或 20 米。
    官方没有一天耗电多少的保证，要你实测；Polarsteps 说它全天约 4%。
- **国产手机会杀后台**：页面上有"去设置里允许后台运行"的按钮，跳到系统的电池优化设置，各家手机的叫法不同，按提示操作。
- **只有安卓 App 有**。网页版（包括 iPhone）做不了后台定位，页面上说明。

## 2. 点存在哪（推荐 A）

- 原生服务把点追加写到 App 私有目录的一个文件里（每行一个点）。
- 打开 App 时，网页从这个文件把新点取出来，存进数据库新表 `track`（数据库 v9），再清空文件。
- 点只存在手机里，进备份；不上传。

| 备选                         | 取舍                                         |
| ---------------------------- | -------------------------------------------- |
| **A 原生先写文件，网页来取** | **选定**。网页没开也能记，网页开了再统一入库 |
| B 原生直接回调网页           | 网页被系统关掉时，点就丢了                   |

## 3. 隐私区（推荐 A）

- 在"偏好"页设一个或几个隐私区（家、公司）：用地名搜索或当前位置定圆心，半径 300 米到 2 公里。
- **圈内的点不进轨迹**：从数据库里取点时就去掉，不存。这样家的位置不会出现在路线、备份和以后的分享链接里。
- 圆心存的时候随机偏移一点（不超过半径的三分之一），借 Polarsteps 和 Strava 的做法，别人不能从圈推出你家在哪。

| 备选                                      | 取舍                                                         |
| ----------------------------------------- | ------------------------------------------------------------ |
| **A 圈内的点直接不存**                    | **选定**。最简单，最安全                                     |
| B 存下来，分享时再藏（Polarsteps 的做法） | 自己看时路线完整；但备份里有家的位置，以后每个出口都要记得藏 |

## 4. 按拍照时间给照片补位置（用户提的，推荐 A）

- 照片自己带位置的，照旧用照片的（最准）。
- 没带位置的（比如微信传过来的），按拍摄时间到轨迹里找：
  - 前后 10 分钟内有点：用最近的那个点；
  - 前后都有点、相隔不超过 30 分钟：按时间在两点之间插值。
  - 都没有：照旧"待定位"。
- 用轨迹补的位置，卡片上标"位置来自轨迹"（`locationStatus: 'track'`），可以改。
- 新导入的记录自动补；已经是"待定位"的老记录，有了新轨迹后在后台再试一次。

## 5. 停留提示（推荐 A）

- 在一个地方 150 米内停留超过 20 分钟，而这段时间那里没有记录，时间线顶部提示"11:20 在 西湖边 停了 1 小时，要记一条吗？"。
- 点"记一条"打开"只写几句"，时间和位置已经填好；点"不用"就不再提示这一次。
- 只提示最近 3 天的，最多 3 个，不打扰。

## 6. 导入别的 App 的轨迹（GPX）

- 备份页加"导入轨迹（GPX）"，读文件里的轨迹点（经纬度和时间），存进同一张 `track` 表，隐私区同样生效。
- 两步路、六只脚、运动手表、Google 地图导出的 GPX 都是这个格式。没有时间的点不要（没法给照片补位置）。

## 7. 交通方式和沿轨迹画路线

- **有轨迹的出行，路线沿着轨迹画**（简化到约 30 米），不再是记录之间的直线；里程也按轨迹算。
- **交通方式**：每两条记录之间的一段，按轨迹自动猜，你可以改。
  - 有轨迹点：按平均速度猜，步行（< 7 公里/时）、骑行（< 20）、开车或公交（< 120）、火车（< 300）。
  - 两点之间轨迹断了很远：用 Polarsteps 的规则（≥ 200 公里且 > 100 公里/时，或 > 1500 公里）判成飞机，画弧线。
  - 没有轨迹：和 0020 一样，超过 300 公里画弧线、不说是什么。
  - 你改的存在后一条记录上（`transport` 字段）。地图上在这一段中间放一个小图标。

## 没做的

- 实时上传位置、给别人看你此刻在哪（第 3 批"跟着看"再说，而且要先有隐私设置）。
- 贴合道路：有了轨迹，路线本来就沿路走，用不着。
- 手机重启后自动恢复记录：要"始终允许定位"，不值得。

## 实现（2026-11-24）

- **原生**：`TrackerService.java`（前台服务，系统定位接口）、`TrackFile.java`（暂存文件）、`TrackerPlugin.java`
  （开始、停止、状态、取点、打开电池优化设置）。清单里加了前台服务、定位类前台服务、通知三个权限。
- **网页**：`src/lib/track.ts`（纯计算）、`src/lib/trackSync.ts`（取点、导入 GPX、补位置）、
  `TrackerCard.tsx`（地图页顶部）、`PrivacyZonesCard.tsx`（偏好页）、`StaySuggestions.tsx`（时间线顶部）。
- 数据库 v9：`track` 表，进备份；导入备份时按时刻去重。记录加了 `transport` 字段，位置状态多了 `track`。
- 打开 App、从后台回到前台时取一次点。

**和上面方案不一样的两处**：

- GPX 导入放在地图页的"记录路线"卡片里，不在备份页：和记录路线放一起更好找；网页版也能用。
- 补位置只补**拍摄时间可靠**的记录（照片自带的拍摄时间，或"只写几句"写下的那一刻）。
  微信传过来的照片常常连拍摄时间也没了，用的是文件时间（保存的时间），按它去轨迹里找会找错地方，所以不补。

## 验证

- 单元测试 14 个：按时间找位置（10 分钟内取最近、30 分钟内插值、太远不给）、停留、隐私区偏移后真实位置仍在圈里、
  GPX（只要带时间的点、顺序、越界的丢掉）、按速度猜交通方式、折线简化、沿轨迹走的一段、轨迹断了按规则判飞机、
  没有轨迹不判飞机、用户改的优先、哪些停留要问。
- 浏览器里用手造的 GPX（西湖边走一圈、中间停 30 分钟、之后飞北京）：
  - 导入 15 个点；一条没带位置、有拍摄时间的记录，按 5 分钟前的点补上了位置，卡片标"位置来自轨迹"；
  - 时间线顶部出现"停了 30 分钟，要记一条吗"，点"记一条"打开"只写几句"、位置已填好，保存后记录时间就是停留开始的时刻，提示消失；
  - 地图上西湖边三段是步行图标，杭州到北京判成飞机（虚线弧线）；点图标改成火车，存到了那条记录上；
  - 出行标题和总览的里程按轨迹算（约 1132 公里）。
- 安卓正式版能编译打包。**没验证**：真机上的后台记录、耗电、国产手机杀后台、通知栏提示，要你装上实测。
