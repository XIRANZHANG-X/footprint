## 1. 使用看板（ideas 六.9，选 A）

目的：最早的计划里说要"连续用两周，记下实际打开了几次"来检验留存假设，到现在都没有数据。

| 备选                                           | 取舍                                            |
| ---------------------------------------------- | ----------------------------------------------- |
| **A 只在本机统计，偏好页里一张表，可导出 CSV** | **选定**。不上传任何东西；数据本来就大多在本机  |
| B 接一个统计服务（如 Umami、Plausible）        | 要把使用行为发出去，违反 0002；个人自用也没必要 |

按周统计最近 12 周，每周一行：

- **打开了几天**：新记的。每天第一次打开 App 时，在本机记一下日期（只记日期，留最近 400 天）。
- **新记了几条**：按记录的创建时间。
- **用语音的比例**：新记的。保存时记下这条的文字是不是从语音转来的（`noteVia`）；以前的记录不知道，不算。
- **AI 稿改动比例**：修改记录里已经有（0012），取这一周改过的稿子的平均改动比例。越来越小说明偏好学习有用。
- **整理用时的中位数**：记录上已经有（0013 第 5 条）。
- **AI 花费**：用量表里已经有（0016）。

## 2. 年度报告（ideas 七.2，选 A）

"回顾"页的"按年"已经有本机统计（记录数、天数、城市、第一次、去得最多、类别）和长图。缺的是一段"这一年"的文字。

| 备选                                                                   | 取舍                                                                       |
| ---------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| **A 分层总结：先每个月写一段（复用出行总结的接口），再由 12 段写一年** | **选定**。每次只发一个月的记录，不会超长；月度总结存起来，记录没变就不重写 |
| B 一次把全年的记录塞给模型                                             | 记录多了超长、贵，也容易漏掉前半年                                         |
| C 不用 AI，只有统计                                                    | 现在就是这样，少了"讲一讲这一年"                                           |

- 月度总结存在本机（`settings` 里，按月份和这个月记录的指纹）。记录改了，这个月下次重写；其他月份不动。
- 年度那一步只发：每个月的总结 + 本机统计（城市、天数、第一次去的地方）。不发照片、不发坐标。
- 年度这页多两项本机统计：哪个月出门最多、最长的一次出行。
- 年度文字会放进长图。

## 3. 多设备同步（ideas 六.4 + 六.5）

### 3a. 存到哪（选 A）

| 备选                                                                            | 取舍                                                                                     |
| ------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| **A 用户自己的 WebDAV 网盘（坚果云、Nextcloud、群晖等），在手机上加密后再上传** | **选定**。服务端仍然不碰数据（0002）；坚果云国内能用、有免费额度                         |
| B 存到本项目的 Cloudflare（KV / R2）                                            | KV 单个值 25 MB、每天 1000 次写入，放不下照片；R2 账号还没开通；而且变成服务端存全部数据 |
| C 只用备份文件，自己拷来拷去                                                    | 现在就是这样；换手机能用，日常两台设备同步不方便                                         |

- **只在安卓 App 里能用**：浏览器不让网页直接访问别的网站的 WebDAV（跨域限制），App 里用原生网络请求没有这个限制。
  网页版的同步卡片说明这一点，继续用备份文件。
- 网盘地址、账号、应用密码存在本机，**不进同步、不进备份**。

### 3b. 怎么加密（选 A）

- 用户另设一个**同步口令**，用 PBKDF2（SHA-256，31 万次）从口令算出 AES-GCM 256 位钥匙。盐和一段校验密文放在网盘的 `meta.json` 里，
  另一台设备输入同样的口令就能解开，输错会立刻提示。
- 网盘上只有密文：`state.bin`（全部记录、想去、计划、偏好等，不含照片原图）和 `photos/<编号>.bin`（每张照片一个文件）。
- 口令忘了就解不开，网盘上的东西只能删掉重来（本机的数据不受影响）。界面上写明这一点。

### 3c. 怎么合并（选 A）

| 备选                                                               | 取舍                                                           |
| ------------------------------------------------------------------ | -------------------------------------------------------------- |
| **A 每一行带修改时间；同一行两边都改了，以后改的为准；删除留标记** | **选定**。规则简单、好验证；两台设备同时改同一条记录的情况很少 |
| B 字段级合并 / CRDT                                                | 更精细；对个人手账来说过度设计                                 |
| C 整份覆盖（谁后同步谁赢）                                         | 最简单；会丢掉另一台设备上新记的东西                           |

- 修改时间（ideas 六.5）：参与同步的表在写入时自动加 `_mt`（数据库钩子统一加，不用改每个写入的地方）。
- 删除标记：删除时在 `tombstones` 表里记下"哪张表、哪一条、什么时候删的"，同步到别的设备也删掉；删除比修改晚就删，早就保留。
- 同步的表：记录、照片、修改记录、想去、去过、计划、跟着看的链接、偏好设置（同步账号相关的除外）、用量、轨迹（轨迹按时间合并）。
- 不同步：草稿、语义向量（每台设备自己算）。
- 上传 `state.bin` 时带上读到时的版本号（ETag）；如果中间被另一台设备改过，就重新读、合并、再传。

## 实现（2026-11-24）

- 看板：`src/lib/dashboard.ts`（打开记录、按周统计、CSV）、`DashboardCard.tsx`（偏好页）；记录上新增 `noteVia`。
- 年度报告：`src/lib/yearStory.ts`（按月分组、记录太多时均匀挑、本机统计、逐月小结 + 年度）、`YearStoryCard.tsx`（回顾页按年）；
  服务端 `/api/summarize` 多了 `scope: month`，新增 `/api/summarize/year`。
- 同步：数据库 v12（`tombstones` 表；参与同步的表由钩子自动写 `_mt`、记删除标记）；`src/lib/sync/`：
  `crypto.ts`（PBKDF2 + AES-GCM）、`webdav.ts`（App 里原生请求，浏览器里 fetch）、`merge.ts`（合并规则，纯函数）、`sync.ts`（整个流程）；
  `SyncCard.tsx`（备份页）。
- 顺带修的：**撤销删除**恢复的记录要比删除标记新，否则同步时会被删掉（`restoreRecord` 写 `_mt`）；
  **备份文件不含同步账号和口令**（备份没有加密）。

## 验证

- 单元测试：看板 2 个（周一起算、按周的各项）；年度 3 个（按月分组、记录多时均匀挑并保留首尾、统计）；
  同步 7 个（两边各取新的、删除标记新就删、删后又改就留、没有修改时间的算最旧、本机设置不同步、轨迹按时间合并、
  口令对才能解开、不同的盐解不开）；服务端 2 个（月度用月度提示词、年度只收小结和统计、空月份拒绝）。
- 界面测试 1 个（Playwright，两个浏览器环境当两台设备，网盘是测试里的假 WebDAV）：A 记两条（一条带照片）并同步 →
  网盘上只有密文 → C 用错的口令被拒 → B 同步后看到两条和照片 → B 删一条、新记一条、同步 → A 同步后多了 B 的、删掉的没了。
- **年度报告真实试跑**（qwen3.7-flash，3 个月的假记录）：4 次调用，约 ¥0.0005。第一次试跑发现两个问题并改了：
  统计写在一行时模型把"6 条记录"写成"六次出行"（改成一行一个数，提示词要求按名称照抄）；"外婆家"被当成外婆的家
  （提示词说明地点是店名或地名）。第二次数字都对。
- **没验证**：真实网盘（坚果云）上的同步（要用户用自己的账号和应用密码试；安卓原生请求的路径没有自动测试）；
  照片很多时第一次同步要多久；看板要用一两周才有数据。
