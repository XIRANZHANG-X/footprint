# 0006 AI 流程：实测结果与暂缓的改进

- 状态：记录（2026-11-06）

## 流程

1. 录音结束后，录音转写成文字（qwen3-asr-flash）。用户要等这一步完成，才能确认或修改文字。
2. 点"完成"后记录立即保存，随后在后台依次进行：GPS 转地名（Nominatim）→ 照片加原话生成正文（qwen3-vl-plus）。

## 实测

- 电脑直连：转写约 5 秒，逐字准确；正文生成约 5 秒，能从招牌认出店名；地名查询约 1 秒。
- 开发者本人的安卓手机：识别准确，地名正确，整体等待时间可以接受，但"整理"这一步偏慢。
- 正文风格偏夸张：会补充用户没说过的感官描写（例如"热气腾腾""浓郁却不腻"）。提示词目前只禁止编造事实（价格、人名、时长），没有限制润色程度。

## 暂缓的改进（开发者决定先不动）

| 问题       | 可选改法                                                                                     | 代价                                                    |
| ---------- | -------------------------------------------------------------------------------------------- | ------------------------------------------------------- |
| 正文太夸张 | 提示词改为只用原话和照片中可见的信息、语气平实；或者把风格做成可选项                         | 风格偏好因人而异，更适合交给第 3 阶段从用户的修改中学习 |
| 整理偏慢   | 地名查询和照片缩小并行进行；正文用流式输出，边生成边显示；换用更快的模型（具体型号需查文档） | 流式输出要改接口和界面                                  |
| 两步串行   | 改用一次全模态调用（音频加图片直接出正文）                                                   | 转写结果无法先给用户确认，已在 0005 中否决              |
